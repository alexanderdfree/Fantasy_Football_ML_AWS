# CLAUDE.md — Claude Code specifics

Everything above (imported from [AGENTS.md](AGENTS.md)) is the shared, provider-neutral project brain — read it first. **This file adds only the Claude-Code-specific machinery**: hooks, skills, the scheduled audit routine, sub-agent/Workflow contracts, and auto-memory. The Codex- and Gemini-side parity for the same disciplines is in [AGENTS.md](AGENTS.md) §§ "Codex specifics" / "Gemini specifics" — keep CLAUDE.md, CODEX.md, and GEMINI.md in sync when you change a shared discipline.

## Hooks (`.claude/settings.json` → `.claude/hooks/`)
- **`session-start.sh`** (SessionStart) — best-effort pull of Claude memory from S3 (always); then auto-links the parent checkout's gitignored `data/{raw,splits}` into the worktree (via `claude_link_worktree_data` in [.claude/hooks/lib.sh](.claude/hooks/lib.sh); idempotent, fail-open, no-op in the main checkout / remote single-clone) so the pre-PR full `pytest -m unit` (which reads `data/{raw,splits}/*.parquet`) works without the manual symlink-from-parent step; then, **only in remote/web sessions** (`CLAUDE_CODE_REMOTE=true`), bootstrap the venv, install deps (requirements + torch CPU + dev), and write `VIRTUAL_ENV`/`PATH`/`PYTHONPATH` to `$CLAUDE_ENV_FILE`. Local sessions stop after the memory pull + data-link (use SETUP.md for the venv).
- **`ruff-format.sh`** (PostToolUse: `Edit|Write|MultiEdit`) — `ruff format` the edited `.py` (silent, fail-open).
- **`guard-worktree-path.sh`** (PreToolUse: `Edit|Write|MultiEdit|NotebookEdit`) — blocks (exit 2) any write whose `file_path` is under the parent root but **not** under `$CLAUDE_PROJECT_DIR`, echoing the corrected worktree path. This is the deterministic backstop for the "edit the worktree, not the parent" gotcha (see [AGENTS.md](AGENTS.md) § Worktree workflow): plan files / sub-agents report parent-absolute paths, and using them verbatim silently edits `main`'s checkout — `git status` stays clean and a benchmark re-run shows MAE Δ=0.0000 (the late smell). Burned ~30 min GPU time on PR #284; recurred on #354, #370, #378. **The manual re-prefix-then-grep habit is still the goal; the hook just catches the miss.** Recovery if it slips: `cp <parent>/<file> <worktree>/<file>` (if committed baselines match) or `git -C <parent> diff -- <file> | git -C <worktree> apply`, then `git -C <parent> checkout -- <file>`.
- **`pre-pr.sh`** (PreToolUse: Bash `gh pr create`) — the deterministic gate: **B1** ruff check + ruff format --check + `pytest -m unit`; **B2** content-fingerprinted benchmark evidence, scoped by [`scope_positions.compute_benchmark_scope`](src/scripts/scope_positions.py) (ANY file under `src/{pos}/` scopes that position; `src/{shared,data,features}/**` + `src/config.py`/`src/__init__.py` = shared arm requiring evidence on ≥1 position; `src/batch/**` + `requirements.txt` exempt-but-reported). A position passes when some `benchmark_history/*.json` entry's `code_fingerprints[POS]` — recorded by all three benchmark writers (`benchmark.py` sequential, `parallel_train.py`, `src/batch/benchmark.py`) — matches the branch HEAD's fingerprint ([`src/scripts/bench_fingerprint.py`](src/scripts/bench_fingerprint.py)), so rebase/stash/checkout mtime churn can't invalidate real evidence and evidence recorded against different code can't pass. Fallback tiers: self-retiring legacy-mtime (active per position only until its first fingerprinted run) and permanent `{pos}/outputs/models` mtime (bare `run_pipeline` evidence, accepted with a nudge). **AST-inert** (comment/docstring/format-only) and additive-only-no-risky-token edits bypass B2; `[docs-only]` bypasses both. The B2 brain is unit-tested Python ([`src/scripts/pre_pr_bench_check.py`](src/scripts/pre_pr_bench_check.py); hook-level pins in [tests/hooks/test_pre_pr_b2.py](tests/hooks/test_pre_pr_b2.py)); an evaluator crash fails OPEN with a loud warning (never wedges the session). Scoped fix commands are printed on failure (~1–2 min/position warm) — don't force a full sweep; fix the gate / surface friction instead.
- **`post-pr-create.sh`** (PostToolUse: Bash after `gh pr create`) — injects the autonomous follow-up workflow below (it only injects the instruction; Claude executes it).
- **`post-pr-merge.sh`** (PostToolUse: Bash after `gh pr merge`) — two best-effort parent-housekeeping steps (helpers in [.claude/hooks/lib.sh](.claude/hooks/lib.sh)). **(1) Fast-forwards the parent/main checkout's `main`** to `origin/main` (`claude_refresh_parent_main`): guarded — skips a non-`main`/dirty parent (it can be another agent's `codex/*` checkout) and uses `pull --ff-only` so it never creates a merge commit or clobbers work. **(2) Promotes a worktree's locally-built `data/splits` to the parent** (`claude_promote_worktree_splits`): when the merging worktree has its OWN `data/splits` (a real dir, not the parent symlink) **and** the merge touched splits-affecting code (`git diff origin/main~1 origin/main | python3 -m src.scripts.scope_positions`), it copies the fresh parquets into the parent so the parent + every symlinked worktree skip the ~10 min rebuild / ~12 min refresh-splits-to-S3 wait — no-op when the worktree just symlinks the parent. `data/splits` is gitignored shared data, so step (2) runs regardless of the parent's git branch (unlike step 1). Shares the parser-aware `gh pr <subcmd>` matcher (`claude_command_invokes_gh_pr_merge`). Emits a one-line status per step; never blocks.
- **`memory-sync-stop.sh`** (Stop) — best-effort `scripts/agent-memory-sync.sh all push`, pushing changed local Claude/Codex memory trees to their separate S3 prefixes.

## The pre-PR / post-PR flow
- **Before `gh pr create`, invoke the `pre-pr-judge` skill.** It is a Claude wrapper over [`agent-workflows/pre-pr-judge/instructions.md`](agent-workflows/pre-pr-judge/instructions.md): diff the branch against `origin/main`, compare against the original task, and flag scope creep — the "agent did more than I asked" failure mode behind the reverted shared-venv ([#110](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/110)/[#111](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/111)) and gunicorn `--preload` ([#148](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/148)/[#149](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/149)) PRs. Skip only for trivial changes — see the shared instructions for the skip list. **Always `git fetch origin main && git rebase origin/main` first**, or the judge sees unrelated newer-on-main files as scope creep.
- **After `gh pr create`, the `post-pr-create.sh` hook injects an autonomous follow-up.** Claude's next turn: (1) `git fetch origin main --quiet && git rebase origin/main` to fold in newly merged PRs (force-push if the rebase changed anything; abort + surface on conflict), (2) invoke the `/review` skill on the PR, (3) auto-apply **every** finding via Edit/Write **except** architectural / design-level ones — nit/minor/style, naming, formatting, dead imports, local logic fixes, localized security fixes, missing-test additions, missing edge-case handlers, doc/comment tweaks, (4) commit auto-applied fixes as `review: address /review nits` and push, (5) if any architectural / design-level finding was surfaced, stop and list them for the user, (6) otherwise wait for green CI via `gh pr checks <N> --watch` then `gh pr merge <N> --squash` and `git push origin --delete <branch>` (worktree-safe). CI failure → stop and surface; never `--admin` bypass. **Exception — solve-issues PRs** (branch `audit-*/tier-*`): step (6) becomes a stop for **explicit user merge sign-off** (show the diff + any `regress-risk-high` benchmark deltas and ask) — the `solve-issues` wrappers mirror this via [`agent-workflows/solve-issues/instructions.md`](agent-workflows/solve-issues/instructions.md). After any `gh pr merge`, the separate **`post-pr-merge.sh`** hook fast-forwards the parent checkout's `main` (guarded; skips a dirty / non-`main` parent) and promotes the worktree's locally-built `data/splits` to the parent when the merge touched splits-affecting code — no manual parent pull / splits copy needed.

## Sub-agent contract — two shapes, picked by batch size
The provider-neutral *consolidation pattern* (file-disjoint bundles → tier-by-risk PRs) is in [AGENTS.md](AGENTS.md); this is the Claude `Agent`/`Workflow` orchestration detail.
- **>10 items** (default for code-review remediation): spawn **as many file-disjoint worker sub-agents as possible**, but workers **DRAFT** commits in their isolated worktrees and do **NOT** push or open PRs. The orchestrator cherry-picks each risk-tier's worker commits onto a fresh staging branch from `origin/main` and opens **one PR per tier**. See auto-memory `feedback_tier_by_risk_pr_consolidation` for the per-tier recipe.
- **<10 truly independent tasks:** the older per-worker-opens-PR shape is fine — each worker commits, pushes, and runs `gh pr create` itself.
- **Either shape:** workers MUST report ship-status (commit SHA, branch, files modified, findings skipped + why); the orchestrator verifies via `gh pr list` / `git log <worker-branch>` — incomplete worker output is a recurring failure mode the orchestrator catches.
- **Claude orchestration gotchas:** worker `pytest` MUST be foreground (a backgrounded run ends the turn before pytest finishes and the transcript is reclaimed); `isolation: worktree` + `run_in_background: true` returns no `worktreePath:` — confirm via `git worktree list | grep agent-`; if a worker runs out of usage with a correct partial diff, take over its worktree directly rather than respawning; checklist finding→worker before spawning and reconcile fixed+leave==total before declaring done; in a `Workflow` script, inline large arrays as `const FILES = [...]` rather than passing them via `args` (`args.map` throws if the harness coerces args to a non-array).

## Scheduled routines
A Claude Code cloud routine (a claude.ai remote agent, on-demand — the recurring cron is disabled; fire it via `RemoteTrigger run`, see the routine README) runs a **codebase audit**: it works through per-area scopes and standing cross-cutting lenses (parallel auditor workers at the agent's discretion), dedupes against open+closed `claude-audit` and `codex-audit` GitHub issues, and files **one issue per finding** labeled `claude-audit` + severity + model regress-risk + area, plus one closed `[claude-audit] checkpoint` issue per fire recording the audited SHA. Codex has a tracked wrapper that can file parallel history under `codex-audit`; both producers share the same master instructions. Those per-finding issues are consumed by the `solve-issues` wrappers ([`.claude/skills/solve-issues/SKILL.md`](.claude/skills/solve-issues/SKILL.md), [`.codex/prompts/solve-issues.md`](.codex/prompts/solve-issues.md)), which both read [`agent-workflows/solve-issues/instructions.md`](agent-workflows/solve-issues/instructions.md) to triage, severity-order, and bundle into tier-by-risk PRs. The actionable backlog is the open severity-labeled issues under either audit label; checkpoints carry no severity label.

The shared audit behavior is version-controlled in [`routines/audit/instructions.md`](routines/audit/instructions.md). Provider wrappers only set runtime/tool rules:
- [`routines/audit/instructions.md`](routines/audit/instructions.md) — shared mission, issue schema, dedupe, stop rules, verification, consolidation, and checkpoint behavior.
- [`shim.md`](.claude/routines/audit/shim.md) — the Claude dashboard shim; at run time it reads the shared instructions and applies Claude-only runtime rules.
- [`prompt.md`](.claude/routines/audit/prompt.md) — compatibility alias kept for any already-deployed dashboard shim that still reads the old path.
- [`config.json`](.claude/routines/audit/config.json) — deploy params (trigger id, model, cron, environment, allowed tools).
- [`README.md`](.claude/routines/audit/README.md) — the edit/push recipe and gotchas.

**To change what the audit does:** edit `routines/audit/instructions.md`, merge to `main` — the next fire picks it up through the wrapper, no dashboard push needed. **To change a deploy param or the Claude shim itself:** edit `config.json` / `shim.md`, then invoke `/schedule` and say "push the audit routine" (see the README). Keep `.claude/routines/audit/prompt.md` tracked as a wrapper unless you have confirmed the deployed dashboard shim no longer reads it.

**Two specialized sibling routines** extend the general audit with deeper, scoped passes that **reuse the same `claude-audit`/`codex-audit` labels, `agent-audit/v1` schema, and dedupe pool** — so they flow into the same `solve-issues` backlog and any overlap with the general audit is auto-suppressed. **tests-audit** ([`routines/tests-audit/instructions.md`](routines/tests-audit/instructions.md); Claude wrapper [`.claude/routines/tests-audit/`](.claude/routines/tests-audit/), Codex [`.codex/automations/tests-audit/prompt.md`](.codex/automations/tests-audit/prompt.md), Gemini [`.agents/routines/tests-audit/prompt.md`](.agents/routines/tests-audit/prompt.md)) deep-audits the test suite (coverage gaps, fixture/`CONFIG_TINY` drift, test↔production parity, flakiness/isolation, markers, stale tests). **infrastructure-audit** ([`routines/infrastructure-audit/instructions.md`](routines/infrastructure-audit/instructions.md); same wrapper layout under `infrastructure-audit/`) deep-audits CI/CD, Batch/EC2 orchestration, Docker, serving/ECS deploy, IAM, and the artifact lifecycle. Each posts its own routine-distinct closed checkpoint (`[claude-audit] tests-audit checkpoint …` / `… infrastructure-audit checkpoint …`). Both are tracked-but-undeployed (empty `trigger_id`) — deploy via `/schedule` (see each routine's README); edit/push mechanics match the general audit.

## After a non-routine session, invoke the `post-session-critique` skill
Run when the user corrected your approach mid-flight, a non-obvious convention bit you, or something went unusually well because of a specific rule. The Claude skill is a wrapper over [`agent-workflows/post-session-critique/instructions.md`](agent-workflows/post-session-critique/instructions.md), which captures *prompt* lessons (proposed AGENTS.md, CLAUDE.md, or auto-memory edits) the way [todo/fixed-archive.md](todo/fixed-archive.md) captures *code* lessons. ## Auto-memory
Claude loads this project's auto-memory automatically each session. The auto-memory dir is **machine-local** by design (official Claude Code behavior) but is synced across the owner's machines via a private S3 bucket by [scripts/agent-memory-sync.sh](scripts/agent-memory-sync.sh) / [scripts/claude-memory-sync.sh](scripts/claude-memory-sync.sh) (#686; see [SETUP.md](SETUP.md) § "Sync agent auto-memory across machines"). Codex memory is synced separately under `codex-memory/<repo>/memories/`; Claude keeps `claude-memory/<repo>/memory/`. That sync is a cross-machine **cache** of incidental recall, **not** a source of truth. [AGENTS.md](AGENTS.md) § "Operating lessons" is the **cross-agent mirror** of the durable subset; the convention going forward: when `post-session-critique` writes a **durable, cross-agent** lesson (ML method, git/PR/CI/env workflow, project fact), add it to AGENTS.md and to any relevant agent memory stores. **Claude-internal harness lessons stay in Claude auto-memory only** — e.g. held/replayed burst output → send ONE call and wait (never fan out 50 identical commands); re-verify garbled/truncated tool output with one clean sequential call before reporting a number; the predictions-bootstrap `#loading-overlay` eats `preview_click`, so drive serving tabs via `preview_eval`; seed the `data/serving_cache/` triple (parquet+metrics+fingerprint) to browser-verify the serving UI with no model artifacts.

**The `MEMORY.md` index is generated, not hand-maintained.** It is a deterministic projection of the topic files, rebuilt from each file's frontmatter **`index_line`** by [scripts/memory_index.py](scripts/memory_index.py) in the SessionStart hook, and **excluded from the S3 sync** (the `claude` branch of [scripts/agent-memory-sync.sh](scripts/agent-memory-sync.sh) carries `--exclude "MEMORY.md"`). That is what makes the index **non-racy**: it is no longer shared mutable state, so concurrent / cross-platform sessions can't clobber each other's index lines. (Prior failure mode: a session overwriting the *synced* `MEMORY.md` wholesale dropped another session's just-added line, leaving the topic file present-but-unindexed — an orphan recall never surfaced.) **Convention when writing a memory:** set its **`index_line`** frontmatter (a `|-` block scalar holding the curated one-liner `[Title](slug.md) — hook`); a `MEMORY.md` line *without* a matching `index_line` is regenerated away next session (and flagged by the generator's description-fallback + the SessionStart orphan canary). Per Claude Code's load order (memory loads **before** SessionStart hooks), a regeneration lands the **next** session — the index stays complete + orphan-free, with cross-session new memories appearing within one cycle. The generator is stdlib-only (the hook runs before any venv) and warns near the ~24.4 KB / 200-line auto-load cap; long-term shrink via the `consolidate-memory` skill.
