# ADR-0011: Smoke-test gate + ordered, conditional artifact publication (manifest v3)

**Status:** Accepted

**Decision.** Training publishes unique immutable artifacts under `models/{POS}/releases/history/`, then conditionally updates `releases/manifest.json` using the ETag read with the previous manifest (or `If-None-Match: *` for initialization). Each source image has an immutable ancestry record under `models/source-revisions/{full_sha}.json`, created by the launcher from full first-parent `origin/main` history. The container verifies the requested SHA against its image-baked `.training-source-sha`. A late-finishing job from an older source cannot advance the pointer; a CAS conflict reloads and rechecks that rule. Passing smoke advances `stable`; failure retains the previous stable while retaining the attempted artifact in `current` and `history`. Superseded normal production uploads raise `PublicationSuperseded` and fail the job without an automatic application retry, so downstream benchmark aggregation cannot label the newer active model as this run. An `initialize_only` seed losing CAS is benign and verifies the winner instead.

**Migration.** Consumers prefer the v3 namespace and read legacy manifests only before the first v3 publication for that position. The first publisher copies every retained legacy artifact into the protected namespace before switching the pointer. Each legacy artifact's embedded `git_sha` must be in the publishing image's lineage; missing or newer provenance aborts without changing the pointer. Register/publish a main descendant of the legacy source, or restore verified provenance before retrying. Existing old-image jobs may continue writing legacy manifests and sweeping legacy history; neither operation can modify the new namespace. Cutover is per position when its first v3 publication succeeds. Boot persists the ETag from the manifest GET it actually consumed in `src/{pos}/outputs/.manifest-etag`; the poller compares its first observation with this sidecar, so a publication between boot and the first poll cannot be silently missed. No live AWS migration or training run is implicit in a code change.

**Retention and rollback.** Online GC deletes only physical keys removed from the reference set by a successful publication CAS. It never enumerates a shared prefix, so it cannot delete another job's unpublished upload. Publishers never reuse physical keys. Manual rollback copies a retained artifact to a fresh protected key, explicitly advances both `current` and `stable`, and preserves the source high-water mark. Queued jobs at or below that source cannot undo rollback; a newer source can advance normally. A racing rollback must win CAS while its target is still retained. Legacy positions must complete a source-registered v3 publication before this operator command can write them. Abandoned uploads and failed cleanup attempts retain extra bytes; offline coordinated cleanup is required for those objects. S3 versioning remains defense in depth.

**Context.** D10's CI gate catches code regressions before they merge; it does not catch artifact regressions — a model that trains successfully but predicts NaN, or whose feature-column hash drifted past the scaler's, will pass pytest and then silently degrade the live dashboard. The weather/Vegas-missing-at-inference incident (TODO archive) is the canonical example: training-pipeline and serving-pipeline drift shipped past every test and only surfaced when users saw zeros in the dashboard. Prior to D11, any successful S3 upload silently became "live" to the next ECS task that booted. Production safety is a core claim of the project; this decision is what backs it.

**Options considered.**

| Option | Safety | Operator cost | CI/CD fit |
|---|---|---|---|
| Always advance — newest upload is live | Low | None | Matches D10's trunk-based ratchet |
| Manual promote step (operator approval before live) | High | Every push needs a human | Defeats D10 |
| **Smoke-test gate + stable/current/previous/history (chosen)** | High | None on success; rollback is a `promote.py` invocation | Compatible with D10 — gate runs in the same CI job |
| ECS canary deploy (split live traffic) | Very high | Needs traffic-splitting infra | Over-engineered for single-task ECS service |

**Chosen rationale.** For an eligible source that wins CAS, the smoke test is *non-fatal*: `current` advances (so failures are visible in the manifest for post-mortem), but `stable` only moves on success. The frontend resolves the artifact pointer at boot from `stable`, so a failed gate means new ECS tasks keep loading the prior good model while a human investigates. PR #179 (`8c42e88`) closed the operational loop: after a successful train, the workflow now issues `aws ecs update-service --force-new-deployment` so the newly-promoted `stable` is actually consumed by a fresh task instead of staying invisible to the long-running one. The smoke test itself ([src/shared/smoke_test.py](../../src/shared/smoke_test.py)) catches the four failure modes that matter at promotion time: pickle/torch.load deserialization errors after class-path drift, state-dict shape mismatches (feature-count drift between training and the runtime registry), scaler `feature_cols_hash` drift caught by `assert_scaler_matches`, and NaN/Inf predictions on benign input from a collapsed head.

**Rejected.** Manual-promote breaks the trunk-based CI/CD ratchet from D10 — every push would need a human. Canary deploys need real traffic-splitting infrastructure absent on a single-task ECS service. Doing nothing and relying on tests proved insufficient (see Context).

**Consequence.** Adds source registration and conditional S3 publication without changing training. Requires full main ancestry at the launcher and immutable image provenance; unsafe or unregistered uploads fail before promotion. Adds ~5 s per training run for the smoke pass. Introduces a two-channel signal — "did training succeed?" splits into `current` (always advances) and `stable` (conditional). Operator scripts must understand which pointer they're reading: model_sync clients consume `stable`; forensics tooling and the `promote.py` listing read `history[]` and `previous`. Trades "newest model always live" for "no NaN-emitting model ever live" — the weather/Vegas archive entry quantifies what the prior behavior cost. The 5-deep `history` plus S3 bucket versioning means even a "two consecutive bad ships" scenario (`current` and `previous` both broken) is recoverable: `promote.py --list` shows older `history[]` entries and `--to <key>` rewrites the manifest atomically. (The legacy `model.tar.gz` mirror is gone — D13 layer C removed the producer write and `legacy_model_key()` was deleted from model_sync.py, so the manifest is the sole pointer.)
