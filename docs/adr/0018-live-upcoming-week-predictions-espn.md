# ADR-0018: Live upcoming-week predictions homepage (ESPN-sourced)

**Status:** Accepted

**Decision.** The serving site gets a forward-looking **homepage** (the new default tab) showing model projections for the **next unplayed NFL week**, auto-refreshed in the background. The week's *live* inputs — schedule, Vegas lines, active rosters, injuries — come from **ESPN's free public API** ([src/serving/espn_live.py](../../src/serving/espn_live.py)); historical context (≤ latest played season, feeding `prior_season_*`) stays on nflverse. Synthetic player-week rows for the upcoming slate are spliced onto full nflverse history and run through the **real offline feature pipeline** (`load_raw_data` → `preprocess` → `engineer.build_features`), then the existing serving inference (`core._apply_position_models`) — so the upcoming week is featurized byte-identically to training. A **scheduled CI job** ([src/serving/upcoming_week.py](../../src/serving/upcoming_week.py) `main`) builds the artifact and uploads it to S3; the serving container only **downloads + serves** it off disk (`sync_artifact_from_s3`); `GET /api/upcoming_week` serves it. **Scope: QB/RB/WR/TE**; K/DST (separate, season-bound pipelines) are a follow-up.

**Context.** The site only showed backward-looking 2025 predictions; the actual fantasy use case is "who do I start next week." nflverse schedules carry only the *closing* line post-hoc and its roster/injury feeds lag, so a live source is required for the volatile inputs — but nflverse remains the only viable source for 10+ years of history. The cardinal risk is feature drift between a bespoke upcoming-week feature build and training; reusing `build_features` verbatim (the [D6](0006-explicit-per-position-feature-allowlist.md) anti-drift rule, mirrored from the [cross-player-feature parity](0016-external-opportunity-quality-value-signals.md) precedent) eliminates it.

**Chosen design.** (1) **ESPN client** isolates undocumented endpoints behind fixture-tested pure parsers; player identity bridges ESPN `athlete.id` → `espn_id` → `gsis_id` via the stable `nfl_source.player_ids()` crosswalk; the spread sign is flipped to nflverse's home-favored-positive convention. (2) **Frame builder** memoizes the historical `build_features` input (stable across polls) and concats synthetic rows (raw stats absent → features come from prior games via shift/rolling, so Week-1 cold-starts exactly as every trained Week-1 row does). (3) **Schedule-cache augmentation** splices the upcoming season's games into the on-disk `schedules_*.parquet` + resets `weather_features._schedule_cache` so `implied_team_total` (the top Week-1 feature) computes — all from `upcoming_week.py`, no `src/shared` edit, so no retrain. (4) **Current-week contextual carry-forward**: the synthetic rows lack the externally-merged per-player columns (`depth_chart_rank`, contracts, injury/practice status); left NaN they fill to a constant and the QB attention head can't separate starters from backups and ~doubles every projection (verified 2026 W1: QB mean 30.7→9.6 after carrying `depth_chart_rank`/contracts forward + defaulting health columns). (5) **Out-of-serving build** — the heavy `load_raw_data` + `build_features` + inference runs in a scheduled CI job ([.github/workflows/refresh-upcoming-week.yml](../../.github/workflows/refresh-upcoming-week.yml): cron every 3h for fresh lines/injuries + on `train-batch` completion for new models + manual dispatch) and uploads the artifact to S3; the serving container `sync_artifact_from_s3` at boot + a lightweight S3-download poller (`FF_UPCOMING_SYNC_INTERVAL_S`, default 10 min), serving `503 warming` until the first build lands.

**Rejected.** (a) *nflverse for the live slate* — it lags; the user requirement is a direct live API. (b) *A separate odds-only API + nflverse for the rest* — only solves the single most-volatile input and still rides the nflverse cadence for rosters/injuries. (c) *In-serving background poller* — tried first (simpler, fresher), but **abandoned after two failed deploys**: running `load_raw_data`/`build_features` in the 2-worker serving task OOM-killed a worker and attempted a runtime 2025-PBP download that failed (SSL), so the new tasks never passed ELB `/health` and the circuit breaker rolled back — at both 2 *and* 4 vCPU. The scheduled-CI build (now chosen, (5) above) keeps that heavy/network work out of serving entirely. (d) *Recomputing only the new rows* — `build_features`' cross-player/season groupbys need the full frame; deferred as a perf optimization.

**Consequence.** Serving-only → triggers `deploy.yml`, **no model retrain**. **Build location (learned the hard way):** two in-serving deploys rolled back — first a worker OOM-kill, then a runtime 2025-PBP download failure — **even at 4 vCPU / 8GB** — because a 2-worker serving task simply can't host the full `load_raw_data` + `build_features` + inference (PBP rebuild + GitHub PBP downloads). So the build moved to a scheduled CI job (ample memory + reliable network) that uploads the artifact to S3; serving downloads + serves it and is back to **2 vCPU / 4GB** (`infra/aws/task-definition.json` + live revision 454). `deploy.yml` also drops the 20-min in-workflow stability wait (`wait-for-service-stability: false`); the ECS circuit breaker still guards prod. ESPN endpoints are unofficial — a schema drift fails `espn_live.py`'s parsers loudly (fixture-tested), not the whole site, and the poller's broad try/except keeps serving up. K/DST are surfaced as "coming soon" until their synthetic-injection paths land.

## Changelog

- **2026-07-02** — **Mid-season cold-start fix (#1411):** design point (2)'s "Week-1 cold-starts exactly as every trained Week-1 row does" reasoning only ever held for Week 1. The featurized frame was sliced to the upcoming week *before* inference, and `core._apply_position_models` rebuilds every within-season lookback from the frame it receives (attention game-history arrays, `shift(1)`-rolling L3s, QB `season_starts_to_date` — all keyed `(player_id, season)` within-frame), so every **mid-season** week served all-padding attention history + train-mean rollups. `build_upcoming_week_frame` now returns the current season's completed REG weeks alongside the context-filled week-W rows, and `run_upcoming_inference` slices **predictions** (not inputs) back to week W. No stateful season-to-date artifact: the CI builder rebuilds from raw every 3h and the rows already existed in the frame — persisted state would only add drift/backfill risk (Rejected (d) still stands for `build_features` itself). Also guarded the away-side `spread_line` negation against odds-less games (`None` → `TypeError` killed the whole refresh, #1400). Serving-only, no retrain; validated by an offline mid-season parity check (week-only ≠ season-to-date; season-to-date == full-split predictions on the same rows).
- **2026-06-30** — The Consequence's "2 vCPU / 4 GB (live revision 454)" is a point-in-time snapshot: serving task memory was later raised to **8 GB** (#1160) for headroom on the off-container upcoming-week build; cpu stayed 2 vCPU.
- **2026-06-08** — Added the live upcoming-week predictions homepage (new default tab) — QB/RB/WR/TE projections for the next unplayed week. ESPN free API for the live slate (schedule/odds/rosters/injuries) via [src/serving/espn_live.py](../../src/serving/espn_live.py); synthetic rows spliced onto nflverse history + run through `build_features` for byte-identical featurization; serve-off-disk artifact (`/api/upcoming_week`). Found+fixed a QB cold-start inflation (missing current-week `depth_chart_rank`/contracts → carry-forward + health defaults). Serving-only, no retrain. See new **D18**.
- **2026-06-08** — Moved the artifact build OUT of serving after two in-serving deploys rolled back (worker OOM + a runtime 2025-PBP download failure, even at 4 vCPU / 8GB): the heavy `load_raw_data`/`build_features`/inference now runs in a scheduled CI job ([.github/workflows/refresh-upcoming-week.yml](../../.github/workflows/refresh-upcoming-week.yml) — cron 3h + on `train-batch` completion + manual) that uploads the artifact to S3; serving only downloads + serves it (`sync_artifact_from_s3` + a 10-min download poller) and reverts to 2 vCPU / 4GB. `deploy.yml` drops the 20-min in-workflow stability wait.
- **2026-06-08** — Replaced the stale `depth_chart_rank` carry-forward (design point (4) above) with the player's **live ESPN depth chart**, and added live injury `game_status`. The carry-forward reached up to 2 seasons back, so a player with no latest-season games inherited a stale rank — Skylar Thompson carried `depth_chart_rank=1.0` from a 2024 spot start, so the attention NN ranked the Ravens' **backup** QB *above* Lamar Jackson (attn 17.6 vs 19.5). New precedence in `_fill_current_week_context` is **live ESPN signal → carry-forward → default**, via `espn_live.fetch_depth_chart_ranks` (ESPN core `/depthcharts`, re-ranked by order + clamped to nflverse's [1,3] scale, prior-season fallback) and `espn_live.fetch_injury_status_map` (ESPN status → the training `game_status` encoding {Questionable 0.5 / Doubtful 0.1 / Out 0.0}). Same-frame A/B: Skylar's attn collapses 17.6 → 4.3 and he leaves the top board; Lamar unchanged. `practice_status` stays defaulted (ESPN exposes no practice participation); weather + contract freshness deferred. Serving-only, no retrain.
- **2026-06-08** — Wired the remaining live current-week signals the prior entry deferred: **`practice_status`** and **`contract_*`**. `practice_status` ← nflverse `load_injuries` (the exact training feed + encoding, Full/Limited/DNP → 2/1/0), with a free **Sleeper** players-dump fallback when nflverse is empty in-season (month-gated so the offseason skips the 14MB fetch); `contract_*` ← nflverse `load_contracts`/OTC via the training `derive_active_contracts` for the current season (advances `contract_age`/`years_remaining` vs the stale carry-forward — e.g. Lamar's 2026 `contract_age` 2 → 3). New `src/serving/live_sources.py` (nflverse + Sleeper, defensive); `_fill_current_week_context` precedence is now **live → carry-forward → default** (depth + contracts) and **live → default** (game + practice health), threaded through `build_upcoming_week_frame` + `_input_signature`. **Holistic source split (researched):** ESPN = the real-time slate (schedule/lines/rosters/depth/game-status); nflverse = the official slower feeds that match training exactly (practice/contracts); Sleeper = practice fallback only (its depth/roster fields are sparser than ESPN offseason → doesn't displace ESPN); no paid feeds. Same-frame A/B: contracts land (Lamar attn 19.46 → 19.32, board sane); practice is a correct offseason no-op (nflverse rejects season 2026, Sleeper month-gated). Weather (Open-Meteo) + opponent-defense remain deferred/structural. Serving-only, no retrain.
