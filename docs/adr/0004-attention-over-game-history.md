# ADR-0004: Attention over game history (all positions)

**Status:** Accepted

**Decision.** Every position (QB, RB, WR, TE, K, DST) replaces pure rolling features with a variable-length game-history branch processed by learned-query attention, fused with the standard static feature vector. All six positions set `POSITION_CONFIG.train_attention_nn = True` and share the `d_model=32` / `n_heads=2` attention shape; K additionally wraps a per-kick inner attention pool inside the outer per-game sequence.

**Context.** Rolling means lose order — "three good games then a bad one" looks identical to "one bad then three good." Attention over the last N games lets the model weight recent games higher, attend more to games pre-injury, and in principle learn role-change signals (backup becomes starter) that a fixed window can't capture.

**Options considered.**

| Option | Signal captured | Sample-efficient? |
|---|---|---|
| Pure rolling features | Mean/variance only | Yes |
| LSTM / Transformer over history | Order + interactions | No (overfits on ~300 rows) |
| Rolling + attention-pool over history (chosen for skill positions) | Both | Marginal |
| Rolling + attention-pool over per-game sequence (chosen for DST) | Both | Marginal |
| Rolling + nested (per-kick ⊕ per-game) attention (chosen for K) | Per-kick conditions + per-game order | Marginal |

**Chosen: learned-query attention pool on every position.** A small attention head (`d_model=32`, 2 heads) is cheap enough not to overfit, with positional encoding for recency. Originally the skill positions (QB/RB/WR/TE) shipped with attention and K/DST stayed on rolling-only; subsequent measurements showed that with the right history channels (raw defensive stats for DST, per-kick rows for K) the attention branch paid for itself on both. The implementations differ:

- **QB / RB / WR / TE** — outer attention over prior games; each per-game token carries the player's own stat line plus the realized game environment of that game (game-script context + final score / margin), so attention can learn a player's *conditional* response to matchup/script — the matchup-driven boom/bust signal a player-only history is blind to. RB pioneered this; WR/QB/TE adopted the game-script + final-score tokens on 2026-06-05 (QB omits team passing volume as collinear with its own passing line). See the 2026-06-05 changelog entry.
- **DST** (commit `cc0c627`) — outer attention over prior games using a 14-stat per-game sequence (the 10 raw targets plus 4 raw opponent-context columns `opp_scoring`, `opp_fumbles`, `opp_interceptions`, `opp_qb_epa`, see [src/dst/config.py:246-263](../../src/dst/config.py)). No gated fusion, no gated TD head.
- **K** (commit `801b61a`) — **nested attention**: the outer attention is over prior games, but each game token is itself produced by an *inner* attention pool over up to `attn_max_kicks_per_game=10` (the `PositionConfig` field set in [src/k/config.py](../../src/k/config.py)'s `POSITION_CONFIG`) kicks within that game (with per-kick features like `kick_distance`, `fg_prob`, `is_q4`, `game_wind`, see [src/k/config.py:160-213](../../src/k/config.py)). The inner pool summarizes per-kick conditions; the outer pool weights which prior games matter. This lets the model distinguish "3-for-3 from short range in a dome" from "3-for-3 in a blizzard from 50+" — a signal pure per-game rollups destroy. A subsequent refinement (PR #199, `dff43fb`) dropped the L1-rolling columns (`ATTN_L1_FEATURES`) that K had still been feeding into its attention static branch: once the inner per-kick attention pool was learning per-game aggregates directly, the L1 rollups were redundant signal, and keeping them violated the "no rolling features in the attention static channel" rule the other five positions already followed.

**Empty-history (season-opener) handling — `attn_no_history_embedding` (2026-05-30).** A season-opener row (`n_prior_games==0`) has an all-padding history sequence, so `AttentionPool` returns a zero vector that the per-target LayerNorm maps to its constant bias — the head then leans entirely on the static prior-season branch and over-predicts. The knob (on for all five flat-attention positions; K's nested path is excluded) swaps that dead vector for a per-target **learned** embedding gated on `history_mask.sum(dim=1)==0`. Zero-initialised and constructed last so it draws no RNG and is bit-identical to the baseline at init — important because it makes the OFF/ON A/B exactly ceteris-paribus, which is how the gain was attributed cleanly (deterministic Ridge/NN/LGBM identical across the pair). The correct home for this signal is the **player-history** branch only: a *mirror* onto the opp-defense branch was tested and rejected because opp-history is empty iff week 1 and every week-1 player is already a season opener (`opp-empty ⊆ player-empty`), so the opp embedding only double-counts the opener signal and dilutes the player correction — the same "encode one signal in one place" discipline as D6's no-rolling-in-the-static-channel rule.

**Rejected.** A full LSTM or Transformer was tried conceptually (see [docs/archive/design_lstm_multihead.md](../archive/design_lstm_multihead.md)) but rejected as over-parameterized for this regime. Kept the design doc as an artifact of the consideration. An earlier version of this ADR rejected attention on K and DST — that decision was reversed once the input schemas were redesigned to give the attention branch something real to chew on (raw per-kick rows for K, raw defensive stats rather than pre-rolled windows for DST).

## Changelog

- **2026-06-15** — **Opponent-defense attention branch disabled for QB/RB/WR/TE.** The second `AttentionPool` over the opposing defense's per-game history (added 2026-04-23 #123 for QB/WR/TE, 2026-05-20 #214 for RB; activated by a non-empty `opp_attn_history_stats`) is set to `[]` in each `POSITION_CONFIG`, reverting the attention NN to its single-branch (pre-#123) shape. A 24-seed **stacked** Batch A/B on the production GPU metric path ([src/tuning/ab_opp_def.py](../../src/tuning/ab_opp_def.py), run `ab_opp_def-20260615T061654Z`) measured the branch ON vs OFF and found it does **not** improve the attention NN: attn-NN MAE ON→OFF QB **−0.074** (and ON is 6× noisier — std 0.316 vs 0.050), RB **−0.027**, TE **−0.013**, WR **+0.009** (within ~1σ); the Q4 boom tier shows no systematic gain either. This **overturns #214's single-seed eager claim** (−0.164 RB) — the canonical "single-seed NN MAE is noise" failure mode. The branch only ever touched the attention NN (Ridge/NN/LGBM Δ=0.000 across all 192 cells), so disabling it is attention-only; the **static** `opp_def_*_L5` aggregates stay in `INCLUDE_FEATURES["defense"]` for Ridge/LightGBM. DST keeps its separate opp-**offense** branch (`opp_attn_kind="offense"`, untested here). Caveat: the A/B ran in the stacked LN/FP32/fixed-30-epoch regime (within-mode ON/OFF is the valid comparison); the post-merge eager retrain produces the authoritative `benchmark_history` numbers.
- **2026-06-05** — **Per-game game-script + final-score tokens for WR/QB/TE/K history.** The history sequence was *environment-blind* for WR/QB/TE (player stat line only) and carried only the Vegas implied total for K, so a 120-yard game in a 45-42 shootout looked identical to one in a 13-10 grind and the NN could not learn a player's conditional response to game script — the mechanism behind matchup booms/busts (predictions were "flat" across the season). Added the per-game game-script + realized-final-score tokens RB already carries to `attn_history_stats`: WR/TE gain `implied_team_total`, `implied_opp_total`, `is_home`, `days_rest`, `team_points_scored`, `opp_team_points_scored`, `team_pass_attempts`, `team_passing_yards`, `team_rush_attempts`; QB the same minus `team_pass_attempts`/`team_passing_yards` (collinear with its own attempts/passing_yards already in the sequence); K gains only `team_points_scored` (it sets `_schedule_merged` in [src/k/data.py](../../src/k/data.py), short-circuiting the schedule merge that produces `implied_opp_total`/`days_rest`; and its frame carries no schedule-matching `opponent_team`, so `opp_team_points_scored` would merge to a dead constant-zero column and is omitted). **Config-only** — every added column is already materialized at train time by `build_position_features` ([src/shared/feature_build.py](../../src/shared/feature_build.py): schedule + `team_box_score` merges) before `build_game_history_arrays` runs, so no splits regeneration / S3 re-upload. Leakage-safe (prior in-season games only; current-week counterparts stay on the static branch). Same eligible-reach discipline as D6 (per-game context on the history branch, not rolling features on the static branch). Benchmarked on the Batch retrain of WR/QB/TE/K — judged on per-target MAE *and* the `Var(pred)/Var(actual)` spread / matchup-extremity metric (the direct "are predictions still flat" check), since the overall-MAE delta is expected small (game-script is a minority of the week-to-week variance, most of which is irreducible).
- **2026-06-01** — Replaced stale module-level `{POS}_TRAIN_ATTENTION_NN` / `{POS}_ATTN_STATIC_FEATURES` wording with the current `POSITION_CONFIG` fields. Documentation-only.
- **2026-05-31** — **Newest-first history ordering.** The per-game attention sequences are now built most-recent-first (index 0 = last game, older games at higher indices, right-padded) instead of oldest-first. With the learned `attn_positional_encoding` (on for all six positions), the old oldest-first layout put the most-recent game at index `n_real-1` — a *different* absolute index per player depending on history length — so the positional embedding at any given index meant a different recency for everyone. Newest-first fixes each index to a constant "games ago", giving the embedding a consistent recency signal (recency dominates fantasy output). Applied uniformly across all three sequence builders: player game-history (`build_game_history_arrays`, all 6), opponent-defense (`build_opp_defense_history_arrays`, QB/RB/WR/TE/DST), and K's nested outer-game order (`build_nested_kick_history`). ALiBi (production-off; ablation-only) was kept recency-correct under the new convention: `games_ago == position index` (was `n_real-1-position`). Pure permutation of real games under a *learned* positional embedding, so not bit-inert — retrained and benchmarked.
- **2026-05-30** — D4 extended: **learned no-history embedding** for empty-history (season-opener) rows. A row with no prior in-season games (`n_prior_games==0`) has an all-padding history sequence → `AttentionPool` returns a zero vector → the per-target LayerNorm maps it to its constant bias, so the head fell back entirely on the hot static prior-season branch and over-predicted (RB opener bias **+1.13**, the worst non-Ridge model — the weak spot flagged in [src/analysis/rb_lgbm_disagreement_findings.md](../../src/analysis/rb_lgbm_disagreement_findings.md) Part 2). New `attn_no_history_embedding` `PositionConfig` knob (on for all five flat-attention positions QB/RB/WR/TE/DST; K's nested path excluded) swaps the dead vector for a per-target **learned** embedding, gated on `history_mask.sum(dim=1)==0`; zero-init + constructed last ⇒ draws no RNG ⇒ bit-identical to baseline at init ⇒ the flag OFF/ON A/B is exactly ceteris-paribus (Ridge/NN/LGBM MAE identical to 6 d.p.). Validated on the real pipeline: RB opener bias +1.13→+0.52, opener MAE 3.81→3.39 (seed 42, confirmed across a 2nd seed — direction robust, magnitude seed-sensitive since the baseline opener problem is itself seed-driven); QB/WR/TE/DST (seed 42) all non-negative — QB opener −0.245 MAE, DST overall −0.065, WR/TE flat-to-mild — no history-depth bucket regresses, overall MAE flat-to-slightly-better. **Rejected sub-variant:** mirroring the embedding onto the opp-defense branch — a defense's in-season history is empty iff week 1, and every week-1 player is also a season opener, so `opp-empty ⊆ player-empty` (99 ⊂ 159 RB rows); the opp embedding reaches no row the player embedding doesn't, double-counts the opener signal, and dilutes the player correction (degraded RB to opener bias +0.86 / overall 4.25).
