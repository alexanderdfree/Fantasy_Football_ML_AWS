- **2026-05-31** — D12: AMP-precision **`FF_AMP_DTYPE` opt-in + TF32** (FP16 stays the default everywhere; BF16 measured and rejected as a default). The NN autocast dtype now routes through `amp_dtype()` ([src/shared/utils.py](../src/shared/utils.py)). **FP16 + GradScaler remains the default on every CUDA device** — T4 (sm_75), the **new L4/g6 Spot host (sm_89, see entry above)**, and Blackwell (RTX 5080 sm_120) alike: a deterministic RTX 5080 A/B (QB/DST, FP16 vs BF16) showed **BF16 regresses high-magnitude heads** — QB `passing_yards` +2.21% (attention NN) / +3.06% (base NN), headline `attn_nn_mae` +2.20% — because BF16 trades mantissa bits (7 vs FP16's 10) the model uses for exponent range it doesn't need (GradScaler already covers FP16 underflow), and FP16 runs full-throughput Tensor Cores on Ada/Blackwell anyway. The mantissa mechanism is architecture-independent, so this is **direct evidence against the L4-migration entry's "enable BF16" follow-up** — re-measure on L4 before flipping it. BF16 is **opt-in only** via `FF_AMP_DTYPE=bf16`, and *still* sm_80+-gated (it degrades to FP16 on T4 so the opt-in can't reintroduce the #293/#301 T4 hang); `fp32` disables AMP. CPU/MPS stay AMP-off → byte-identical to FP32. Also enables **TF32** for FP32 matmuls via `torch.set_float32_matmul_precision("high")` in `_nn_device` — kept because it's a hardware no-op on Turing (T4) and CPU/MPS yet accelerates the FP32 path on Ada/Blackwell (e.g. under `FF_AMP_DTYPE=fp32`); skipped under deterministic mode. The 5080 A/B confirmed TF32 has no measurable effect on the AMP path (det == non-det numbers). Net: **zero production-numerics change** (default is FP16, = prior behaviour); this adds an experimentation knob + the Ada/Blackwell FP32 speedup. Tests: [tests/shared/test_device_selection.py](../tests/shared/test_device_selection.py). Relates to **D12** and the g6/L4 migration entry above; companion env-profile work in [scripts/wsl-env.sh](../scripts/wsl-env.sh) + SETUP.md's WSL section.

- **2026-05-30** — Documented the **2021 16→17 game schedule expansion** as a known, contained covariate shift (analysis only — no code change, no retrain). The NFL went from 16 games / 17 weeks (≤2020) to 17 games / 18 weeks (2021+); `TRAIN_SEASONS=2012–2023` ([src/config.py](../src/config.py)) therefore pools both regimes while `VAL=2024`/`TEST=2025` are 17-game — so the 17-game era is **trained and tested, not extrapolated**. The design contains the break almost everywhere: targets are **per-game raw stats** (game-count-invariant — the primary protection); rolling/EWMA/trend/share features **reset per season** (`groupby(["player_id","season"])`, [src/features/engineer.py](../src/features/engineer.py)) so they are not rescaled; the attention history sequence is indexed by **games** with `attn_max_seq_len=17`, which exactly fits a 17-game season (intentional — *not* a truncation bug; a team plays 17 games across 18 weeks, so "18 weeks" ≠ "18 games"); and `week` (now 1–18) is already represented in TRAIN via 2021–2023, so week-18 is not novel at inference. The lone real leak is the `prior_season_total_*` features (`prior_season_total_yards` / `_touchdowns` / `_redzone_touches`, full-season **sums** in [src/features/engineer.py](../src/features/engineer.py)), which carry a ~6.25% (17/16) season-length inflation at equal per-game productivity — partially self-mitigated by the per-game-mean prior aggregates beside them and the `prior_season_games_played` active-games normaliser, and small next to the injury-driven games-played variance that already exists. No season-total *projection* exists in the targets/backtest, so there is no hidden hardcoded-16 bug. **Verdict:** minor and contained; the totals are **kept by design** (they carry availability/volume signal the per-game means don't) — revisit them with a measured counterfactual diagnostic (e.g. via [src/analysis/covariate_shift.py](../src/analysis/covariate_shift.py)) only if a future benchmark regression points there, and revisit `attn_max_seq_len=17` only if the NFL moves to 18 games. Analysis only, no decision changed; relates to **D1** (the temporal split pools the two regimes) and the eval-methodology covariate-shift guard, and is topically adjacent to the late-season wk17/18 rest-effect analysis ([#608](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/608)). - **2026-05-30** — D4 extended: **learned no-history embedding** for empty-history (season-opener) rows. A row with no prior in-season games (`n_prior_games==0`) has an all-padding history sequence → `AttentionPool` returns a zero vector → the per-target LayerNorm maps it to its constant bias, so the head fell back entirely on the hot static prior-season branch and over-predicted (RB opener bias **+1.13**, the worst non-Ridge model — the weak spot flagged in [src/analysis/rb_lgbm_disagreement_findings.md](../src/analysis/rb_lgbm_disagreement_findings.md) Part 2). New `attn_no_history_embedding` `PositionConfig` knob (on for all five flat-attention positions QB/RB/WR/TE/DST; K's nested path excluded) swaps the dead vector for a per-target **learned** embedding, gated on `history_mask.sum(dim=1)==0`; zero-init + constructed last ⇒ draws no RNG ⇒ bit-identical to baseline at init ⇒ the flag OFF/ON A/B is exactly ceteris-paribus (Ridge/NN/LGBM MAE identical to 6 d.p.). Validated on the real pipeline: RB opener bias +1.13→+0.52, opener MAE 3.81→3.39 (seed 42, confirmed across a 2nd seed — direction robust, magnitude seed-sensitive since the baseline opener problem is itself seed-driven); QB/WR/TE/DST (seed 42) all non-negative — QB opener −0.245 MAE, DST overall −0.065, WR/TE flat-to-mild — no history-depth bucket regresses, overall MAE flat-to-slightly-better. **Rejected sub-variant:** mirroring the embedding onto the opp-defense branch — a defense's in-season history is empty iff week 1, and every week-1 player is also a season opener, so `opp-empty ⊆ player-empty` (99 ⊂ 159 RB rows); the opp embedding reaches no row the player embedding doesn't, double-counts the opener signal, and dilutes the player correction (degraded RB to opener bias +0.86 / overall 4.25).
