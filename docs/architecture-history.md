- **2026-05-31** — Serving/analysis: **per-projection prediction intervals** (80% floor–ceiling bands) for the expert sources, building on the per-source residual-σ entry directly below (the conditional version of the same residual panel). [src/analysis/expert_intervals.py](../src/analysis/expert_intervals.py) quantile-regresses actual PPR points on each source's projection, per position, at τ = 0.1 / 0.5 / 0.9 (linear `QuantileRegressor`, monotone-rearranged so floor ≤ median ≤ ceiling), reusing [build_comparison_summary.py](../src/analysis/build_comparison_summary.py)'s join plumbing; band width scales with the projection level via the per-τ slopes. Fits on genuine pre-2025 player-weeks, validates **held-out 2025** coverage (the key calibration check). **Data-quality discovery:** the calibration check surfaced a **look-ahead leak in the third-party hvpkod/NFL-Data archive** (the community scrape of NFL.com, *not* NFL.com itself) — its **2021, 2022 and 2023** NFL.com offense "projected" CSVs are backfilled with the realized box score, proven by an exact-match test (the archive's projected raw passing yards equal the actual ~92–96% of the time, e.g. 2023 Josh Allen "projected" 359 / actual 359, and are whole integers vs 2024+'s fractional projections). A naive pooled fit crashed held-out coverage to ~0.40. The decisive fix was the *detector*: residual-std flags only the fully-copied 2023, but a season ~40% backfilled keeps a normal-looking std (genuine rows dominate the variance) while the copied rows pile up at residual≈0 — so the leak guard tests the **near-exact fraction** (drop a season if >30% of rows land within 0.5 pt of the actual), which catches all three; a stationarity guard backs it up. Net: NFL.com offense fits on its only genuine pre-2025 season (2024), landing every cell at ≈0.72–0.82 vs nominal 0.80; NFL.com K and all of RotoWire are clean every season (RotoWire sanity-checks the provenance caveat the *opposite* way the task expected — note the σ entry below independently reached the same "RotoWire clean" read). NFL.com K stays totals-only (standard scoring); coverage holes (NFL.com no DST, RotoWire no K) carry through. Surfaced in the Comparison tab: the bands ride along on `/api/comparison` (committed [src/serving/expert_intervals.json](../src/serving/expert_intervals.json)), a calibration table + per-player-week example band bars + a CI-pinned coverage contract. Serving/analysis-only (`src/analysis/` + `src/serving/`), **no retrain**. Tests: [tests/analysis/test_expert_intervals.py](../tests/analysis/test_expert_intervals.py), [tests/test_app_comparison.py](../tests/test_app_comparison.py). Companion archive entry in [TODO.md](../TODO.md) for the NFL.com look-ahead.
- **2026-05-30** — Comparison tab extended with **per-source projection uncertainty**. Neither expert feed (NFL.com, RotoWire) ships a std-dev/interval — both are point projections — so we *derive* one: [src/analysis/expert_uncertainty.py](../src/analysis/expert_uncertainty.py)::`compute_expert_reliability` scores each source against actuals over a multi-season archive (2018–2025; NFL.com lacks 2020 in the hvpkod archive) and reports per-source × position **residual σ** + bias (σ = sample std of `projection − actual`, matching `analysis_nflcom_baseline`'s `std_resid`; `RMSE² = bias² + population-variance`, so σ isolates the noise RMSE conflates with bias), with a per-season breakdown. [src/analysis/build_comparison_summary.py](../src/analysis/build_comparison_summary.py) embeds it as a new `expert_reliability` key in the committed [src/serving/comparison_experts.json](../src/serving/comparison_experts.json) (via a deferred import to avoid the helper-import cycle); `/api/comparison` passes it through; the tab renders a "Source reliability — residual σ" table (expert-only). **Model side omitted by design** — it has no leakage-free multi-season held-out residuals (every season but the 2025 test split was trained on). RotoWire flagged provenance-unverified (backfill would understate σ); empirically its σ (≈7.9 at QB) ≈ NFL.com's (≈7.8), so no look-ahead signal. K is NFL.com totals-only (flagged); DST is RotoWire-only — same coverage holes as the head-to-head. Analysis (`src/analysis/`) + serving only ⇒ **no retrain**. Tests: [tests/analysis/test_expert_uncertainty.py](../tests/analysis/test_expert_uncertainty.py) + [tests/test_app_comparison.py](../tests/test_app_comparison.py). Per-projection prediction intervals (quantile floor/ceiling bands) landed in the 2026-05-31 follow-up above. Extends the Comparison tab entry below.
- **2026-05-30** — Standing CI guards against the depth-chart off-by-1 class (follow-up to the `week-alignment` fix below). Two checks in [refresh-splits.yml](../.github/workflows/refresh-splits.yml) after the covariate-shift guard, gating the splits→S3 upload — warn-first, `DEPTH_ALIGN_HARD_FAIL=1` to hard-fail (mirrors `COVSHIFT_HARD_FAIL`): (1) **alignment** — `alignment_from_caches` ([src/analysis/audit_depth_alignment.py](../src/analysis/audit_depth_alignment.py)) reconstructs the chart's rank-1 QB from the loader's emitted canonical depth cache ⋈ the weekly `rosters` cache (which lists *rostered* incl. benched players, so it isn't fooled by who-played) and asserts it matches the actual week-W starter (`qb_starters` off the weekly cache), failing on the `SHIFTED_BACK_1` fingerprint or overall<0.80; (2) **week-range canary** — `depth_week_range_check` flags any season whose canonical depth max week overruns the schedule's REG max (the 1–19-for-18-games fingerprint / a reverted `week-=1`). A first *splits-based* draft of (1) was a false negative — the built splits drop no-snap rows, so the chart's benched rank-1 QB is absent and `min(depth_chart_rank)` just tracks who-played; the cache-join (via rosters) is the fix, verified to reproduce the audit's stale signal (cur 0.22 / prev 0.70) on pre-fix data. Tests: [tests/analysis/test_depth_alignment.py](../tests/analysis/test_depth_alignment.py). Extends the depth-chart `week-alignment` fix below; no retrain.

- **2026-05-21** — Optuna NN tuner: trials now skip Ridge / ElasticNet / LightGBM / base NN via four new `cfg.get("train_*", True)` gates (Ridge + base NN gates new; ENet + LGBM already existed) and a short-circuit early return in [src/shared/pipeline.py](../src/shared/pipeline.py) when `ridge_test_preds` or `nn_test_preds` is `None`. The Optuna objective at [tune_nn.py:243-251](../src/tuning/tune_nn.py) only reads `result["attn_history"]["val_loss"]`, so every other model trained per trial was wasted compute — Ridge ≈ 6.1 s + base NN 10–30 s + LGBM ≈ 15 s, gated only by the CPU/GPU branch overlap PR [#267](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/267) introduced (`max(cpu, gpu)` per trial). The CPU branch (Ridge tune + LGBM) had also been the binding constraint on `n_jobs > 1` in `study.optimize` on the 4-vCPU g4dn.xlarge — skipping it unlocked `n_jobs=2` (two concurrent attention-NN trials fit comfortably in T4 16 GB and underutilize Tensor Cores). Combined expected win: ~2–3× tuning wall-clock; smoke-trial measurement deliberately deferred. Production training is byte-identical (all gates default `True`); regression coverage in [tests/k/test_attn_pipeline.py](../tests/k/test_attn_pipeline.py)'s new `test_tuner_shape_returns_attn_history_and_skips_other_models`.
