### [FIXED] Batch CE stuck on g4dn — `setup.sh` reconcile updated the launch template but never `instanceTypes`
- **File(s):** [../infra/batch/setup.sh](../../infra/batch/setup.sh) (reconcile branch now diffs + updates `instanceTypes`; `INSTANCE_TYPE` single source of truth), the live `ff-gpu-spot` CE (migrated `g4dn.xlarge`→`g6.xlarge`), and the g6/L4 doc/label re-alignment across [../src/batch/launch.py](../../src/batch/launch.py), [../src/batch/benchmark.py](../../src/batch/benchmark.py), [../.github/workflows/train-batch.yml](../../.github/workflows/train-batch.yml), [../AGENTS.md](../../AGENTS.md), [../docs/batch_design.md](../../docs/batch_design.md) (revert of #936/bcc1206, now that the migration is real).
- **What:** The 2026-05-31 ADR-0013 g4dn→g6 migration flipped `instanceTypes` in setup.sh's CE-**create** block and instructed operators to run `bash infra/batch/setup.sh` to reconcile the live CE. But the "CE already exists" branch only reconciled the **launch template** — it never read or updated `instanceTypes`. So every re-run was a silent no-op on instance type and the live `ff-gpu-spot` CE kept launching `g4dn.xlarge` (T4, sm_75) for a week. Found 2026-06-07: the live CE was still g4dn (#936/bcc1206 reverted the docs to match reality instead of fixing the migration), which kept CUDA graphs / `torch.compile` / BF16 gated off (sm_75 < sm_80) even though the autodetect was live.
- **Fix:** (1) Migrated the live CE directly: `DISABLE → update-compute-environment --compute-resources instanceTypes=[g6.xlarge] → ENABLE` (minvCpus=0 ⇒ no fleet disruption; confirmed `VALID`/`ComputeEnvironment Healthy`). (2) Closed the reconcile gap — setup.sh now queries `instanceTypes[0]`, enters the DISABLE→UPDATE→ENABLE cycle when **either** the launch template **or** the instance type drifts, and the UPDATE sets both; `INSTANCE_TYPE` is shared by the create + reconcile paths. (3) Re-applied the g6/L4 docs + the conditional `g6.xlarge (Spot, CUDA-graph)` benchmark label that bcc1206 reverted. g6 = sm_89 ⇒ graphs autodetect ON ⇒ benchmark history rebaselines graphed-vs-graphed (`FF_BATCH_CUDA_GRAPH=0` forces eager).
- **Lesson:** An idempotent provisioner is only as trustworthy as the set of fields its *reconcile* path diffs. Reconciling a subset (launch template) silently ignores edits to the rest (instanceTypes): the committed IaC says g6, `git status` is clean, the operator runs setup.sh and sees "success" — yet the live resource never changes. When extending such a branch, diff **every** field the create block sets. And verify infra against `aws … describe-*`, not the committed IaC — "declared" ≠ "deployed."
