### [FIXED] Season Leaders expert columns were only partially live after cache recompute
- **File(s):** [../src/serving/core.py](../../src/serving/core.py) (expert season filter + prediction-cache fingerprint/schema bumps), [../tests/test_app_expert_predictions.py](../../tests/test_app_expert_predictions.py) (future-row regression), [../tests/test_app_predictions_cache.py](../../tests/test_app_predictions_cache.py) (expert/non-serving raw cache fingerprint regressions), live S3 `models/predictions_cache/` artifacts.
- **What:** After the analysis-import rollback fix reached ECS, one load-balanced task generated `snapshot.json` while the other still returned `404`, because `data/serving_cache` is local task storage and no shared S3 prediction cache existed. The generated snapshot also had `rotowire_pred` populated but `nflcom_pred` all null: the expert loader derived seasons from every row in the in-memory results frame, and a future/upcoming row made `nfl_source.rosters(...)` request season `2027`, which nflreadpy rejected (`Season must be between 1920 and 2026`). Because NFL.com is optional, serving swallowed the exception and shipped stable-but-empty NFL.com columns. The next S3 cache seeds also missed because the prediction-cache fingerprint included local `data/raw/` files that fresh ECS tasks do not have before hydrate: first expert loader caches (`nflcom_projections_*`, `sleeper_projections_*`), then developer-checkout/analysis caches such as contracts and redzone.
- **Fix:** Derive expert-source seasons from the configured historical `TEST_SEASONS` before calling NFL.com/RotoWire loaders, leaving future rows null without poisoning played-season coverage. Restrict raw-data fingerprinting to the production serving input allowlist (including the current v2 depth cache and generated runtime inputs that must be S3-seeded with the cache, such as K PBP and team stats), bump the predictions-cache schema to reject stale/badly-keyed artifacts, and publish a shared cache artifact to S3 so every ECS task hydrates the same snapshot instead of recomputing independently.
- **Lesson:** A new column being present in one live response is not enough when ECS tasks have isolated disk. Verify the endpoint across multiple load-balanced hits, check non-null source coverage, and build/seed shared serving caches from the same raw-input contract ECS sees, not from whatever happens to be present in a developer checkout.
