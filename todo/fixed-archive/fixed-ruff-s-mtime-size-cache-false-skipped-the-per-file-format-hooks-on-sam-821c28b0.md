### [FIXED] Ruff's mtime+size cache false-skipped the per-file format hooks on same-size same-mtime-tick rewrites
- **File(s):** [../.claude/hooks/ruff-format.sh](../../.claude/hooks/ruff-format.sh), [../.codex/hooks/ruff-format.sh](../../.codex/hooks/ruff-format.sh), [../.gemini/hooks/ruff-format.sh](../../.gemini/hooks/ruff-format.sh), [../.claude/hooks/pre-pr.sh](../../.claude/hooks/pre-pr.sh) B1, pinned by `tests/scripts/test_cross_model_parity.py::test_ruff_format_hook_disables_cache` (PR #1422).
- **What:** `ruff format <file>` keys its cache on (mtime, size). Two writes of same-size content can land in the same mtime tick on a fast box (reproduced on WSL2: identical `mtime_ns` for back-to-back writes), so the second format was a cache hit and the file silently stayed unformatted. Surfaced as `test_gemini_hooks.py::test_ruff_format_formats_written_python` failing deterministically locally (its loop rewrites same-size content within one tick) while green in CI — false-blocking the local pre-PR gate; the same mechanism could let `ruff format --check .`/`ruff check .` in the B1 gate pass what a cache-less CI runner flags.
- **Fix:** `--no-cache` on the three per-file format hooks (a hook formatting one just-written file gains nothing from the cache) and on the pre-pr B1 `ruff check` / `ruff format --check` (CI parity: CI runners have no cache), plus a content-pin parity test so a refactor can't silently drop the flag on one provider.
- **Lesson:** A "deterministic" formatter invocation isn't deterministic if a cache keyed on filesystem metadata sits in front of it — on fast same-size rewrites the mtime tick is the real key. When a hook/gate must mirror a clean-runner CI check, run it cache-less; when a flaky test's failing iteration differs only in *timing*, suspect metadata-keyed caching before test logic.
