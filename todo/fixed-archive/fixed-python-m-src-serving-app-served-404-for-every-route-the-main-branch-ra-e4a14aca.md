### [FIXED] `python -m src.serving.app` served 404 for every route — the `__main__` branch ran a route-less duplicate Flask app
- **File(s):** [../src/serving/app.py](../../src/serving/app.py) (`__main__` branch), regression test [../tests/test_app_entrypoint.py](../../tests/test_app_entrypoint.py). PR #1148.
- **What:** The serving decomposition made app.py the composition root: it imports routes.py at the bottom, and routes.py imports back (`from src.serving.app import app`) to register handlers. Under `python -m src.serving.app` (the documented local dev command, SETUP.md § "Run the Flask app locally"), sys.modules holds only `__main__` — not `src.serving.app` — so routes.py's back-import re-executed app.py as a *second* module instance. Every `@app.route` handler registered on the second instance's Flask app, while `__main__`'s `app.run()` served the first, which carried only the errorhandler + Flask's built-in `/static` (1 url rule vs 22 on the canonical instance) — every endpoint 404'd. Production (gunicorn `src.serving.app:app`) imports the module by its canonical name only and never runs the `__main__` branch — unaffected.
- **Fix:** The `__main__` branch now serves the canonical instance: `from src.serving.app import app as _canonical_app` (a cached sys.modules lookup by that point — routes.py's back-import already created and fully routed it), then `_canonical_app.run(...)`. Handlers also read shared mutable state via `app_pkg` (= the canonical `src.serving.app`), so serving that instance is what keeps cache/locks consistent too. Regression test executes app.py under `runpy.run_module(..., run_name="__main__")` with `Flask.run` patched and asserts the served instance *is* `src.serving.app.app`.
- **Lesson:** A module that is both a composition root (imported back by name from the modules it imports) and a `-m` entrypoint executes as TWO module instances under `python -m` — `__main__` and the canonical name. Anything the back-importing modules attach (routes, shared state) lands on the canonical instance, so the entrypoint branch must look itself up by canonical name instead of using its own globals.
