### [FIXED] Codex PR hooks stopped matching raw quoted command text
- **File(s):** [../.codex/hooks/lib.sh](../../.codex/hooks/lib.sh) (shared shell-aware PR-create matcher), [../.codex/hooks/pre-pr.sh](../../.codex/hooks/pre-pr.sh) and [../.codex/hooks/post-pr-create.sh](../../.codex/hooks/post-pr-create.sh) (matcher adoption + compact post-PR context), [../scripts/codex-review-quiet.sh](../../scripts/codex-review-quiet.sh) (filtered review wrapper), [../tests/scripts/test_codex_hooks.py](../../tests/scripts/test_codex_hooks.py) (true/false matcher, hook, and review-wrapper regressions), [../CODEX.md](../../CODEX.md) / [../AGENTS.md](../../AGENTS.md) (docs).
- **What:** Codex attached both pre-PR and post-PR hooks to every Bash tool call, then self-filtered by regexing the raw command string. Commands that merely mentioned the PR-create phrase as quoted search text, echo arguments, or comments could trigger the deterministic pre-PR gate or inject the full post-PR review/CI/merge workflow as high-priority context. That explained sessions running out of context after PR work and made hook debugging itself risky.
- **Fix:** Centralize matching in a Bash tokenizer that looks only at unquoted top-level command segments, skips leading env assignments, accepts `gh` or a path ending in `/gh`, and requires `pr create` as the next two argv words. The post hook now emits a compact pointer to `/prompts:post-pr-followup` instead of inlining the whole workflow, and the prompt uses `scripts/codex-review-quiet.sh` so known Codex/plugin loader warnings do not flood the transcript during review.
- **Lesson:** Agent hooks that run on broad tool events must parse command position, not grep raw shell text. For context-injection hooks, keep the injected payload short and put durable workflow details in versioned prompt/skill files.
