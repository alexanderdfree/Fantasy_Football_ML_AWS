### [FIXED] K weather features (`game_wind`/`game_temp`) zeroed by catch-all fillna, not train-mean-filled
- **Files:** `src/k/run_pipeline.py` (`CONFIG["specific_features"]` switched from `SPECIFIC_FEATURES` to `ALL_FEATURES`), `src/k/config.py` (`CONFIG_TINY` mirrored), `src/shared/registry.py` (K `get_inference_spec` mirrored to keep training/inference paths in lockstep).
- **What:** PR #234's K signal-floor diagnostic flagged a 0.12 fpts MAE gap between an in-script Ridge fit (test MAE 3.957) and the production K Ridge (4.079) on the same data. Suspicion fell on the production CV alpha grid (np.logspace(-1, 4, 15) — too coarse / too high?). A controlled experiment ruled alpha out: forcing alpha=1.0 across every K target moved test MAE less than 0.005. The real culprit was in `src/shared/feature_build.py::build_position_features`. K's `fill_nans_fn` is called with `cfg["specific_features"]` — historically just `SPECIFIC_FEATURES` (the 12 rolling stats), not `CONTEXTUAL_FEATURES`. So `is_dome` / `game_wind` / `game_temp` (PBP-derived, NaN for 227/529 test rows in 2025 due to missing weather data) skipped the train-mean fill and got caught by `build_position_features`'s final catch-all `df[feature_cols].fillna(0)`. Result: test `game_wind` mean collapsed from 7.8 mph → 4.5 mph and `game_temp` from 59.6°F → 34.0°F (filling missing-weather rows with 0 not 65 / 8) — a distribution shift the train scaler didn't anticipate. Every K model trained on this miscalibrated test matrix.
- **Fix:** Single-character semantic change at three sites: `"specific_features": SPECIFIC_FEATURES` → `"specific_features": ALL_FEATURES`. `build_position_features` now passes `ALL_FEATURES` into K's `fill_nans`, which routes `game_wind` / `game_temp` / `is_dome` through `fill_nans_with_train_means`. The catch-all `.fillna(0)` becomes a no-op for these columns (nothing left to fill). New full-pipeline test MAE (no alpha-grid change): Ridge **3.886** (-0.193), NN **3.972** (-0.156), Attn **4.043** (-0.089), LightGBM **4.058** (-0.003 — LGBM handles NaN natively so was already mostly OK). The schedule-merge contextual columns (`implied_team_total`, `is_home`, `total_line`) are already non-NaN at fill time so widening the column set is a no-op for them. Other positions are untouched: they don't have PBP-derived weather columns in their feature lists, and their schedule-merge columns already get pre-filled inside `merge_schedule_features` (via `temp.fillna(65.0)`, `wind.fillna(0.0)`).
- **Lesson:** Catch-all `.fillna(0)` at the *end* of a feature pipeline destroys train-mean-fill semantics for any column the per-position `fill_nans` doesn't cover. The signal looks like "Ridge needs better alpha tuning" or "K is at the noise floor" — both wrong. K is unique here because its raw PBP loader emits weather columns with real NaN holes; other positions get pre-filled weather via the shared `merge_schedule_features` path. Companion lesson: when a diagnostic's "best in-script model beats production" claim shows up (PR #234's signal-floor categorical recommendation), the gap is almost never the model class — diff the data preparation paths, not the alpha grid.
