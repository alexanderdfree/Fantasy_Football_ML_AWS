### [FIXED] Inheritance out-set never matched relocated/gamebook team codes — `inherited_opportunity` silently 0 for OAK/SD/STL + ARZ/BLT/CLV/HST/SL seasons
- **File(s):** [../src/features/engineer.py](../../src/features/engineer.py) (`_build_inheritance_features` out-set keys; `_OUT_SET_TEAM_NORMALIZATION`), audit issue #1269, 2026-07-01 solve-issues tier-C-high PR.
- **What:** The vacancy out-set was keyed on the RAW injuries `team` / rosters `team`, looked up against the weekly frame's `recent_team`. Injuries/rosters carry legacy relocation codes (OAK/SD/STL) for pre-relocation seasons — and rosters 2012–2015 additionally use **gamebook** codes (ARZ/BLT/CLV/HST, Rams as `SL` not `STL`) — while `recent_team` is retroactively modern, so for those franchise-seasons the lookup never matched: `inherited_opportunity` stayed 0 and `is_top_available` ignored the vacancy, exactly when a starter was Out/IR. Every sibling team-keyed merge in the file normalized both sides; the inheritance join (added #1104–#1133) was missed. Verified on data/raw: 134 Out/Doubtful + 38 RES/INA skill rows under legacy codes, 0 legacy codes in `recent_team`.
- **Fix:** `_OUT_SET_TEAM_NORMALIZATION` = shared `TEAM_CODE_NORMALIZATION` ∪ {ARZ→ARI, BLT→BAL, CLV→CLE, HST→HOU, SL→LA}, applied to both out-set sides. Kept local to the out-set — other shared-map consumers join schedule/injury universes where gamebook codes never appear. Offline (engineer.py → splits): required splits rebuild + QB/RB/WR/TE retrain.
- **Lesson:** "Schedules carry legacy codes" was an incomplete map of the source universes — injuries/rosters do too, and rosters' pre-2016 codes are gamebook-style, so even the shared relocation map misses the Rams (`SL`). When normalizing a team-keyed join, enumerate the ACTUAL code universe of *each* source frame (`df["team"].unique()` per season band), not just the relocation triple; the first adversarial review pass caught the OAK/SD/STL fix itself missing 5 of 7 mismatched teams.
