### [FIXED] core_pool `AF_UNIX` coordinator crashed on macOS — `sun_path` guard hard-coded Linux's 108, not macOS's 104
- **File(s):** [src/shared/core_pool.py](../../src/shared/core_pool.py) (`_SUN_PATH_MAX` platform constant; new `_socket_path` helper; `start_coordinator` calls it instead of the inline `>= 108` guard). No test change — [tests/shared/test_core_pool.py](../../tests/shared/test_core_pool.py) already drives the coordinator through the returned `addr`, so the short-path fallback is transparent to it.
- **What:** The three `test_core_pool.py` coordinator round-trip tests (and any real parallel-trainer run on a Mac) died with `OSError: AF_UNIX path too long` at `bind()`. `start_coordinator` built `<socket_dir>/core_pool.sock` and guarded it with `len(addr) >= 108` — Linux's `sun_path` capacity. **macOS/BSD's `sun_path` is only 104 bytes**, so a 104–107-byte path (pytest's per-test `tmp_path` under the session's long `/private/tmp/claude-501/...` `$TMPDIR` lands at ~106) slipped past the 108 guard and then hit the real kernel limit at bind. Linux/CI never saw it (shorter runner tmp paths + the genuine 108 limit), so it shipped green in #670.
- **Fix:** `_SUN_PATH_MAX = 104 if sys.platform == "darwin" else 108` (the true per-platform limit), plus a `_socket_path()` helper that keeps `<socket_dir>/core_pool.sock` when it fits but falls back to a short `/tmp/ffcp-<sha1(socket_dir)[:12]>.sock` when the requested dir is too deep — so the coordinator *works* on a deep-`$TMPDIR` Mac instead of raising. Production/Linux is byte-identical (short run dirs always take the requested path; the fallback never fires) and the no-op-without-`FF_CORE_POOL_ADDR` contract is untouched. Full `pytest -m unit` → 2303 passed (was 3 failed) on macOS under the Claude `$TMPDIR`.
- **Lesson:** `AF_UNIX` `sun_path` is **104 on macOS/BSD, 108 on Linux** — never hard-code 108. The kernel measures the *path string handed to `bind`*, so a deep parent dir (a long `$TMPDIR`, pytest's nested `tmp_path`) overflows it before the filename does; when you don't control the caller's dir depth, bind in a short canonical root (`/tmp`) with a hashed name rather than asserting the path fits. A many-core/CUDA-box feature whose socket path is only exercised by tests on the dev Mac is exactly where a platform-specific limit hides from Linux CI.
