### [FIXED] DST `spread_line` and `div_game` silently zeroed by `merge_schedule_features` name-collision
- **Files:** `src/shared/weather_features.py:140-243` (added `spread_line` and `div_game` to the upfront drop list so the merge produces them fresh, AND removed them from the cleanup-drop loop so the merged values survive; `merge_cols` and the lookup builder already carried both columns so no further wiring was needed). `tests/shared/test_weather_features.py` (new `test_spread_line_and_div_game_survive_when_present_on_input` regression that mirrors the DST input shape — bare `spread_line`/`div_game` placeholders already on `df` — and asserts both columns survive with `.std() > 0` and `div_game.unique() ⊇ {0, 1}`). Identified as **H2** in a code-review pass.
- **What:** DST materializes `spread_line` and `div_game` on every row directly from the schedule (`src/dst/data.py:340-360`), so by the time `build_position_features` called `merge_schedule_features`, those columns were already bare names on `df`. The shared helper's upfront drop list was `WEATHER_FEATURES_ALL + ["implied_total_x_dome"]`, and `WEATHER_FEATURES_ALL` does NOT include `spread_line` or `div_game` (they live in DST's `_ALL_FEATURES` / `attn_static_features`, not the weather set). So both columns survived the drop, collided with the lookup's same-named columns during `df.merge(lookup, ...)`, and pandas suffix-renamed to `spread_line_x` / `spread_line_y` and `div_game_x` / `div_game_y`. The merge-back loop only read bare names (`if col in df_merged.columns: df[col] = df_merged[col].values`), so it silently skipped the suffix-renamed pairs. The cleanup loop then unconditionally dropped bare `spread_line` and `div_game` from `df`. End state: both columns gone, and `build_position_features`' catch-all backfill filled them with 0 + printed `WARNING: 2 feature columns missing, filling with 0`. DST trained and served for months without ever seeing point-spread or divisional-game signal. `is_divisional` was recomputed correctly from the original `div_game` BEFORE the cleanup drop, so that derived flag survived; only the raw features were dead.
- **Fix:** Picked Option B (architectural fix in `weather_features.py`) over Option A (local drop in DST's `data.py`): the symmetric "drop upfront + skip in cleanup" pattern makes the helper robust to any future position that carries these columns, and avoids encoding "DST is special" into the position file. Added `spread_line` and `div_game` to the upfront drop so the merge produces clean bare-name columns, and removed them from the cleanup-drop list so the merged values survive. `merge_cols` already includes both, so the merge-back loop now populates them on `df`. Locally re-ran `python -m src.benchmarking.benchmark DST`: Attn NN total MAE 5.288→5.113 (-0.175 pt), ridge_top12 0.500→0.509, points_allowed Attn NN MAE 7.342 (NN was 7.657) — the attention static branch now sees real spread_line/div_game signal where before it saw zero columns. Ridge / NN / LGBM total MAEs moved within ~0.03 pt (platform noise floor for the local CPU/MPS run). Serving paths inherit the fix automatically because they use the same shared helper.
- **Lesson:** The shape of this bug — a column survives a drop list, then collides with a merge that suffix-renames it, then a downstream cleanup unconditionally drops the bare name — is a class, not a one-off. The drop list and the cleanup-drop list both encoded "weather columns" implicitly, but they used different mechanisms (one enumerated `WEATHER_FEATURES_ALL`, the other hand-listed columns) and drifted out of sync without anyone noticing because `build_position_features`' catch-all backfill silently masked the missing columns by filling them with 0. Two structural prevention rules to lift: (1) when a merge function drops and re-populates a set of columns, the drop list, the merge-cols list, and the cleanup-drop list should reference the same source-of-truth set so they cannot diverge — duplicating "weather columns" by hand in three places guarantees this bug class will recur. (2) The catch-all "fill missing feature columns with 0" backfill in `build_position_features` is the masking layer that turned a 1-rev refactor mistake into months of dead-feature training — `WARNING: 2 feature columns missing, filling with 0` was printed every run and ignored. A test that runs each position's real config through `build_position_features` and asserts every declared feature has `.std() > 0` (or at minimum is non-constant when the underlying schedule is not constant) would catch the next instance immediately. M3 in the code-review remediation plan covers this — worth landing.
