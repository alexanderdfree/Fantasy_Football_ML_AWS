### [FIXED] K `pred_*_total` columns inflated because `build_pipeline_config` skipped `aggregate_fn` for K
- **Files:** `src/shared/position_pipeline.py:262-266` (removed the `if pos != "K"` guard so `cfg["aggregate_fn"] = aggregate_fn_for(pos)` is unconditional), `tests/k/test_pipeline_e2e.py` (new `test_build_pipeline_config_registers_k_aggregate_fn` regression). Identified as **H1** in a code-review pass.
- **What:** `build_pipeline_config` had an `if pos != "K":` carve-out that left `cfg["aggregate_fn"]` unset for K. Downstream, `src/shared/pipeline.py::_total(preds)` falls back to `sum(preds[t] for t in targets)` when no aggregator is registered. K's four targets are `[fg_yard_points, pat_points, fg_misses, xp_misses]` with `target_signs = [+1, +1, -1, -1]`, so the naive sum *added* `fg_misses` and `xp_misses` instead of subtracting them. Corrupts every K `pred_*_total` column (ridge / nn / attn / lgbm), the `compute_ranking_metrics` rankings driven off those columns (`ridge_top12` etc. in `benchmark_history/{run_id}.json`), and the weekly backtest table that consumes the same columns. Serving was unaffected — `src/serving/app.py:599-600` already applies `target_signs` directly. The fantasy-point MAE/R² fields (`ridge_mae`/`nn_mae`/...) were also unaffected because `src/shared/evaluation.py::compute_target_metrics` already routes through `predictions_to_fantasy_points` regardless of `cfg["aggregate_fn"]`. The K CV path has the same root cause (`src/shared/pipeline.py:1888-1892`), but K is `has_cv_runner=False` so currently dormant — the factory fix repairs it for free.
- **Fix:** Removed the `if pos != "K"` guard. `aggregate_fn_for("K")` already existed and returns a partial of `_k_predictions_to_fantasy_points`, which implements the correct `+fg_yard_points + pat_points - fg_misses - xp_misses` formula. New `tests/k/test_pipeline_e2e.py::test_build_pipeline_config_registers_k_aggregate_fn` pins the contract: build the cfg, call `cfg["aggregate_fn"]` on synthetic preds with non-zero misses, assert the result equals the signed sum (and is strictly less than the naive sum). Locally re-ran `python -m src.benchmarking.benchmark K`: ridge_top12 0.468→0.505, nn_top12 0.477→0.523, attn_nn_top12 0.403→0.514, lgbm_top12 0.449→0.468 — every K ranking metric improved because the previous ranking treated more-misses as if it were more-points.
- **Lesson:** When a fix introduces a function and leaves one caller's wiring "to be done later," tag the leftover skip with a comment that names the missing wiring — `if pos != "K":` without context reads as deliberate. The earlier [FIXED] NN aux total-loss entry shipped the correct intent ("`aggregate_fn` stays registered for benchmark-ranking reporting") but left K out because K's pipeline at the time hadn't grown an aggregator yet; once `_k_predictions_to_fantasy_points` landed the guard should have been removed in the same PR. Companion lesson: any time a `_total(preds)` helper has a `fall back to sum()` branch, that branch is a footgun for *any* position whose targets aren't all-positive — assert position-aware wiring at config-build time rather than rely on a fallback that silently lies for sign-flipping target sets.
