### [FIXED] Attention NN MAE/RMSE missing for QB/RB/WR/TE in the Comparison + Model-Performance tabs — stale serving container after an architecture-changing retrain; in-flight poller can't heal it, no post-train ECS rollover
- **File(s):** [../.github/workflows/train-batch.yml](../../.github/workflows/train-batch.yml) (new `ecs_rollout` job + `ECS_CLUSTER`/`ECS_SERVICE` env; `warm_cache` now `needs: [train, ecs_rollout]`), [../docs/adr/0014-serving-prediction-cache-post-fork-pre-warm.md](../../docs/adr/0014-serving-prediction-cache-post-fork-pre-warm.md) (changelog), [AGENTS.md](../../AGENTS.md). No serving-code/model change. PR pending.
- **What:** On fantasy.alexfree.me the Comparison tab (and Model Performance tab) showed "—" for the Attention NN's MAE/RMSE on **QB/RB/WR/TE only** (K/DST fine) for ~4 days (2026-06-15→06-19). `/health` was `degraded` with `QB_attn_nn: RuntimeError('Error(s) in loading state_dict for MultiHeadNetWithHistory: Unexpected key(s)… opp_game_encoder…; size mismatch heads.passing_yards.0.weight [32,256]↔[32,192]')`. Root cause: PR #1175 disabled the opp-defense attention branch for QB/RB/WR/TE (`opp_attn_history_stats=[]` → **two-branch → single-branch** attention NN). The retrain correctly promoted a single-branch `stable` artifact to S3 (verified: `models/QB/…/12ecf40`, 638 KB, no `opp_*` keys, head dim 192). But serving builds the model architecture from the **current `PositionConfig`** (single-branch) and loads whatever checkpoint is on disk — and the long-running ECS task (booted 06-15T07:25, before the 07:36 artifact) was still holding the old **two-branch** checkpoint. The in-flight refresh poller *did* swap the on-disk tarball to single-branch at 07:36 (CloudWatch `[refresh] QB swapped … source=stable`), yet the task kept serving the mismatch — and with no deploy for 4 days and `/health` returning 200 for a degraded-but-serving task (so ALB never recycled it), nothing forced a clean reload until an unrelated dependabot deploy on 06-19 started fresh tasks that boot-synced the single-branch artifact. (Ridge/NN/LGBM kept working for those positions because #1175 didn't change *their* architecture — only the attention head's, which is why the symptom was attention-NN-specific.)
- **Fix:** Re-add a per-train serving rollover (the thing PR #330 removed): a dedicated `ecs_rollout` job (`needs: train`) runs `aws ecs update-service --force-new-deployment` + `wait services-stable`, mirroring train-ec2.yml's long-standing "Refresh ECS service" step. A clean container boot re-runs `sync_models_from_s3` and reconstructs+loads the model fresh, so an architecture-changing retrain reaches prod deterministically; `services-stable` makes a failed reload **loud** (red workflow) instead of silent NaN. It's its own job (off the benchmark-commit/dedup-marker critical path, like `warm_cache`) and NOT `continue-on-error`. The poller stays as the between-train fast-path for weight-only retrains. The live symptom had already self-resolved via the 06-19 deploy (verified all 6 positions return `attn_nn`); this prevents recurrence.
- **Lesson:** The in-flight model-refresh poller hot-swaps the on-disk *tarball*, but serving reconstructs the NN architecture from the live `PositionConfig` and `load_state_dict`s the checkpoint into it — so a retrain that changes a model's **architecture** (not just weights) can leave a running task with an unloadable checkpoint, and the poller's hot-swap alone won't fix it: it needs a clean container boot. PR #330's "poller replaces the post-train ECS rollover" optimization was only safe for weight-only retrains. When a per-position artifact's *shape* can change between deploys, force a rollover after training. Debugging tells: the symptom is per-model + per-position (only the head whose arch changed, only the retrained positions); `/health`'s `position_load_errors` carries the exact `load_state_dict` mismatch; the S3 `stable` artifact can be correct while the *running* task is stale, so verify the artifact (download + inspect `state_dict` keys) AND the running container separately — a degraded-but-serving task returns `/health` 200, so ALB won't auto-recycle it.
