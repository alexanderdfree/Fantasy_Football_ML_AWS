### [FIXED] "Verify model artifact freshness" step pointed at deleted `models/{POS}/model.tar.gz` mirror
- **Files:** [.github/workflows/train-batch.yml](../../.github/workflows/train-batch.yml) (line 247: `--key "models/$POS/model.tar.gz"` → `--key "models/$POS/manifest.json"` + 4-line comment explaining the choice and the legacy-mirror history); [.github/workflows/train-ec2.yml](../../.github/workflows/train-ec2.yml) (line 259: same one-character change + mirrored comment).
- **What:** Both training workflows' "Verify model artifact freshness" step called `aws s3api head-object` against `models/{POS}/model.tar.gz`, then compared its `LastModified` to `train_started_at` and failed the workflow if the artifact was missing or > 1200 s older than train-start. That legacy mirror key was retired by the parallel-train-batch race fix (commits `f65bcbe` *delete legacy model.tar.gz mirror* + `be56b0d` *finish race-fix cleanup*) — `src.batch.train.upload_artifacts` now writes only the versioned `models/{POS}/history/{ts}-{sha7}/model.tar.gz` plus the atomic `models/{POS}/manifest.json` promotion. Audit of the live S3 state on 2026-05-21 confirmed the legacy `models/QB/model.tar.gz` object still existed but was last modified at 07:35 UTC while every fresh `manifest.json` had an 11:24-11:26 UTC `LastModified` — i.e. the legacy mirror had gone stale ~4 h earlier when the race-fix landed in production, and the next training run on any of the six positions would have tripped `STALE (>1200s before train start)` and failed the workflow. The check was protecting against the right *failure mode* (artifact predating this run) but anchored on the wrong *sentinel*.
- **Fix:** Switched the `head-object --key` argument to `models/{POS}/manifest.json` in both workflow YAML files. Manifest is the atomic last write of `upload_artifacts` (after history-key upload + remote tarball validation + smoke test, see `src/batch/train.py:418`), so its `LastModified` is a strictly stronger freshness signal than the tarball ever was — the manifest only exists if the entire upload pipeline completed successfully. Pre-existing logic (1200s threshold, `train_started_at` anchor, Markdown summary table, MISSING/STALE/OK branches) all transfer unchanged. The "Size (MB)" column now reports the manifest's ~1 KB size; left as-is rather than renamed because its original purpose (sanity-check that the object isn't zero-byte) still holds. Added a 4-line comment above the `head-object` call in both files pointing at the `upload_artifacts` atomicity property and naming the race-fix commits, so a future reader can't unwittingly revert to the legacy mirror. Precedent: `src/shared/model_sync.py` (the in-flight serving refresh poller from PR [#302](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/302)) already uses `manifest_key(prefix, pos)` for the same kind of S3 head-check; this brings the CI gate into alignment with the consumer side.
- **Lesson:** When deleting an S3 key, grep workflow YAML (`aws s3 ...`, `aws s3api ...`, `s3://` URIs) in addition to Python source. The race-fix PRs caught every Python consumer (`src.shared.model_sync._sync_one`, `src.batch.benchmark.download_metrics`) but missed the two shell `head-object` callers in CI workflow YAML, where the symptom is a CI gate that fails an entire training run rather than a runtime exception in code. Companion lesson on stale-mirror failure modes: a deleted-but-not-truly-absent S3 object is *more* likely to slip past review than a 404, because the gate evaluator (`echo '{}'` fallback in the bash) treats only `head_object` errors as "missing" — a real object with a stale `LastModified` flows through to the timestamp-comparison branch and produces a `STALE (Xs before train start)` message that reads as "artifact corruption" rather than "the gate is wired wrong." When swapping an artifact-pointer convention, audit by *running* the gate against the new convention's expected state, not by grepping for the old artifact name. Companion structural lesson: the atomic last-write of a multi-step upload (here: `write_manifest` after smoke test) is the strictly correct freshness sentinel — the *intermediate* artifact (the tarball at the versioned history key) may exist on disk after a partial-success run that ultimately failed the smoke test; the manifest's promotion is the boundary between "training started" and "training succeeded."
