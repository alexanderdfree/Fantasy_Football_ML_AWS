### [TESTED] Attention-architecture default-OFF extensions (PRs #109–121) — 6 rejected; `condq` adopted for RB+WR+TE on an RMSE re-screen (WR a data-gap forward bet, #1210)
- **File(s):** [../src/shared/neural_net.py](../../src/shared/neural_net.py) (`attn_*`-gated extensions incl. `SelfAttentionBlock`), [../src/tuning/ablate_attn_arch.py](../../src/tuning/ablate_attn_arch.py) / [../src/tuning/ab_attn_arch.py](../../src/tuning/ab_attn_arch.py), run via the Batch path [../src/tuning/launch_ablate.py](../../src/tuning/launch_ablate.py) / `launch_ab` (#1180). condq enablement: `PositionConfig.attn_condition_queries_on_static` (default False) plumbed through `build_pipeline_config` AND `registry._{flat,nested}_attn_kwargs_static` (served-kwargs), `=True` in [../src/rb/config.py](../../src/rb/config.py) + [../src/wr/config.py](../../src/wr/config.py) + [../src/te/config.py](../../src/te/config.py).
- **What:** The seven default-OFF attention flags from 2026-04-23 (#109 temp, #112 seqdrop, #115 swiglu, #116 entropy, #117 alibi[+alibi_only], #120 selfattn, #121 condq) shipped tested-but-never-benchmarked (PR #662). Ran on the real pipeline, multi-seed, Ridge sentinel.
- **Round 1 (MAE only, 2026-06-19):** stacked N=24 RB — temp/condq/alibi/seqdrop/alibi_only/swiglu all inside the 0.02 FP-MAE noise floor; `selfattn` confirmed eagerly (RB Δ +0.116, QB +0.076, 14/16 worse, an RB seed +19% — regresses + destabilizes). Initially read as "**none beats baseline**, all kept OFF". (`entropy` un-run — eager-only vmap side-channel.)
- **Round 2 (RMSE re-screen, 2026-06-19/20, runs `condq-screen-stacked-80494dd` + `-kdst`):** the eager ablation extractor had been **silently dropping RMSE** (fixed: capture RMSE — see the `ablate_attn_arch` RMSE PR). On RMSE, `condq` is MAE-flat but **tail-trimming**, and the effect is **position-specific** — RB clear win (RMSE −0.051±0.028, 24/24), TE tail-vs-median tradeoff (RMSE −0.073 / MAE +0.029), K/DST within noise, **WR/QB regress**. Full per-position table + the mechanism are in [docs/adr/0004-attention-over-game-history.md](../../docs/adr/0004-attention-over-game-history.md). → **`condq` ENABLED for RB + WR + TE** (PR #1198, arch-changing retrain): RB on the clean win, TE for the tail (accepting the small median cost), and **WR as an owner forward-bet** — WR's regression is attributed to a *matchup-feature data gap* (WR boom/bust is CB-level/coverage, absent from our features), **not** a broken mechanism, so the architecture goes in now and re-screens when those features land ([#1210](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/issues/1210)); the post-merge eager `benchmark_history` is the authoritative WR test (revert if it regresses materially). **QB stays OFF** (overfit + destabilize); K/DST OFF (noise). The other six flags stay default-OFF.
- **Round 3 (eager confirmation, 2026-06-20, retrain `ac3686f` — authoritative):** the production eager retrain did NOT reproduce the stacked wins — **RB flat** (MAE +0.045 / RMSE +0.011), **TE flat** (+0.004 / +0.003), **WR regresses** (RMSE +0.046, corroborating the screen). Ridge byte-identical across all six (attention-only); K/DST byte-identical, QB moved from #1197 (training-skipped config) not condq. **Kept ENABLED for RB/WR/TE as an owner forward-bet** (stage the arch for #1210), explicitly NOT a measured production win. Serving verified healthy post-roll (all six finite `attn_nn`, `degraded_positions` empty, no NaN); `ecs_rollout` red only on an `aws ecs wait services-stable` 10-min waiter timeout (roll completed in the background).
- **Lesson:** (1) **For a tail/boom-bust flag, judge RMSE, not just MAE** — `condq` looked dead on the MAE-only screen and only surfaced on RMSE; the eager extractor was dropping RMSE entirely. (2) `condq` is a player-side stand-in for the disabled opp-defense branch — it pays off exactly where matchup is a stable, learnable signal (RB workload/run-D/script) and backfires where the conditioning signal is *missing from our features* (WR boom/bust is CB-level/coverage, not in the static vector — a data gap tracked in #1210, not a broken mechanism) or the `cond_proj` param block is too large for a matchup-insensitive high-magnitude head (QB overfit + variance blow-up, the `selfattn` failure mode); it is **not** a blanket win — enable per-position, judging the eager retrain. (3) `condq` adds a `cond_proj` layer (architecture-changing) → it MUST be forwarded on BOTH the training cfg path AND the `registry` served-kwargs path, or serving rebuilds a condq-off model and NaN's loading the condq-on checkpoint (contract-tested by `test_*_attn_kwargs_static_forwards_every_mapped_config_field`). (4) The other six flags: don't re-propose without a tracked subgroup metric; `selfattn` collides with the "larger regressed on 15K-sample positions" stop-rule. (5) **Stacked-FP32 screen ≠ eager-FP16 production:** condq's stacked RB/TE tail wins did NOT transfer to the eager retrain (RB/TE flat, WR regressed) — the post-merge eager `benchmark_history` is the authoritative production signal (single-seed, so noisy, but it's the deployed regime); judge adoption on it, not the stacked screen alone. condq is currently kept as a forward-bet for #1210, not a measured win.
