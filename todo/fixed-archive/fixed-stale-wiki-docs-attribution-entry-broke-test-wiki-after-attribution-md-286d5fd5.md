### [FIXED] Stale `WIKI_DOCS` `attribution` entry broke `test_wiki` after `ATTRIBUTION.md` deletion
- **File(s):** [../src/serving/wiki.py](../../src/serving/wiki.py) (`WIKI_DOCS`; `ATTRIBUTION.md` deleted in #1296 `8c32f5a`).
- **What:** PR #1296 deleted `ATTRIBUTION.md` but left its registry entry (`"attribution": {…, "path": "ATTRIBUTION.md"}`) in `src/serving/wiki.py`'s `WIKI_DOCS` dict. `tests/test_wiki.py::TestWikiRegistryIntegrity::test_every_registered_doc_file_exists` asserts every registered path exists, so the `shared` shard now fails with `WIKI_DOCS references missing files: [('attribution', 'ATTRIBUTION.md')]`. It stayed latent on `main` because #1296–#1299 were all `[docs-only]` (the per-position/`shared` test shards skip via the empty matrix) — the breakage only surfaces on the next non-`docs-only` PR. Every other `WIKI_DOCS` path points to a real tracked file; only `attribution` was stale.
- **Fix:** Removed the stale `attribution` entry (the file was deliberately deleted, not moved). No serving template/nav hardcodes `/wiki/attribution`, and `test_wiki.py` has no count/slug assertion tied to it, so no other edits were needed (the `attribution` hits in `src/qb/diagnose_outliers.py` / `tests/qb/test_diagnose_outliers_smoke.py` / `tests/analysis/test_rb_ascension.py` are unrelated SHAP/injury feature-attribution, not the wiki doc).
- **Lesson:** Deleting a doc that is registered in an allowlist must also drop its registry entry — same allowlist-drift class as a renamed-doc path. And `[docs-only]` commits skip the test shards, so a registry/test break introduced by one can merge undetected and is "eaten" by the next non-`docs-only` PR; grep the allowlist (`WIKI_DOCS`) when adding/removing a tracked doc.
