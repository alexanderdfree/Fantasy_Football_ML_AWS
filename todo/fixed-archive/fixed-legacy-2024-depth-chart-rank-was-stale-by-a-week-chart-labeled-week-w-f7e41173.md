### [FIXED] Legacy (≤2024) `depth_chart_rank` was stale by a week — chart labeled week W reflected week W-1's lineup
- **File(s):** [src/data/loader.py](../../src/data/loader.py) (`_fetch_depth` legacy branch — `game_type=="REG"` filter + `week -= 1` realign), [src/analysis/audit_depth_alignment.py](../../src/analysis/audit_depth_alignment.py) (new read-only audit), [tests/analysis/test_depth_alignment.py](../../tests/analysis/test_depth_alignment.py) (new), [tests/test_data_loader.py](../../tests/test_data_loader.py) (`_fake_depth_charts` / `_two_row_depth_charts` gained `game_type` + `week=2`).
- **What:** The loader merges depth on the current `(player_id, season, week)` and a `.shift()` grep is clean, so the staleness was invisible to code review — but the **source** `week` is stale: for the ≤2024 NFL Data Exchange feed, the chart labeled week W reflects week W-1's lineup. Audited via QB starter-consistency (`src/analysis/audit_depth_alignment.py`): over 2012–2024 QB-change weeks (n=635) the chart's rank-1 QB matched the **prior**-week starter 69–71% vs the **actual** week-W starter only 23–25%, consistent in 12/13 seasons. Overall rank-1-QB-vs-actual-starter match 0.873 at the raw label vs 0.913 at `week-=1` (argmax over shifts ±2; coverage 99%). Backward-looking → staleness, not leakage. Also a train/test skew: the ≥2025 ESPN path (`_normalize_espn_depth`) is already as-of-kickoff (current), so train+val depth was stale while test depth was current. The legacy schema has **no** timestamp column, so the loader can't self-verify (the timestamp-vs-kickoff check is inapplicable; starter-consistency is decisive).
- **Fix:** Realign the legacy branch — `game_type=="REG"` then `week -= 1` — so week-W `depth_chart_rank` is the chart entering week W's game (the argmax-alignment correction; mirrors the ≥2025 ESPN as-of-kickoff path and removes the train/test skew). REG-only because playoff `week` numbers overlap the regular season; the labeled week-1 (preseason) chart drops to week 0 and the "extra" REG week-19 label backfills week 18, so coverage stays ~99%. Changes `load_raw_data` output → **requires a splits rebuild + 6-position retrain** to land; `benchmark_history/` quantifies the model impact.
- **Lesson:** Merge-key-correct ≠ source-semantics-correct. A `.shift()` grep proves the *code* doesn't lag a feature; it says nothing about whether the *data source* labels a snapshot by the right week. When a feature is "known before kickoff," audit its alignment empirically (here: does the chart's rank-1 QB match who actually started?) rather than trusting the merge key. The residual QB-change-week gap after the fix is real depth-chart **inertia** (official charts react to in-season changes ~2 weeks late) — a source limit no uniform relabel fixes.
