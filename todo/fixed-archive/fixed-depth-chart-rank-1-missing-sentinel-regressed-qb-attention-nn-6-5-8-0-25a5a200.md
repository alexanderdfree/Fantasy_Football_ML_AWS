### [FIXED] `depth_chart_rank` `-1` missing-sentinel regressed QB attention NN 6.5→8.0 (2025 season has zero depth-chart coverage)
- **File(s):** [src/shared/feature_build.py](../../src/shared/feature_build.py) (`build_position_features` imputes `depth_chart_rank == -1` to the leakage-safe train mean of real ranks, just before the catch-all `.fillna(0)`; `pd.notna(fill_val)` guard leaves all-sentinel positions constant), [tests/shared/test_feature_build.py](../../tests/shared/test_feature_build.py) (new `TestDepthChartRankSentinel`: impute case + all-sentinel-guard case).
- **What:** After the `build_features()` restoration (entry below) brought the splits back to 284 cols, QB attention NN still sat at **8.066** vs the `9409e7e` baseline **6.513** — a residual the 150-col fix didn't close. A local 2×2 (code × data) + single-column ablation isolated it to `depth_chart_rank`: `9409e7e` (#326) changed the loader's missing-depth fill `fillna(3).clip(upper=3)` → `fillna(-1).clip(-1,10)` ([src/data/loader.py:290](../../src/data/loader.py)), with a comment **explicitly deferring** the consumer-side remediation. The 2025 test season has **zero** depth-chart coverage (`depth_charts_2012_2025.parquet` ends at 2024), so every 2025 row is the `-1` sentinel; the attention NN's `StandardScaler` (fit on train, mean≈1.25/std≈0.43 for QB) maps that constant `-1` to ≈ −4σ → bad extrapolation (passing_yards MAE 68→105). Ablation: swapping only `depth_chart_rank` moved MAE across the whole gap both ways (OLD+NEW-dcr 6.49→8.16; NEW+OLD-dcr 7.94→6.88). The old fill `3` was in-distribution (benign); `-1` is out-of-band (harmful). K never regressed because its `depth_chart_rank` is *always* `-1` (kickers aren't on depth charts) → constant → StandardScaler's zero-variance handling already maps it to 0.
- **Fix:** Consumer-side impute in the single shared `build_position_features` (both training `_prepare_position_data` and serving `_apply_position_models` route through it): replace `-1` with the train mean of real ranks so missing → ≈0 after standardization (neutral "no signal"). Per-position automatically (the function runs per single-position frame: QB 1.25, RB 1.82, WR 1.57, TE 1.64); the `pd.notna` guard skips all-sentinel positions (K). Loader keeps `-1` as the semantic data sentinel; **no split rebuild needed**. Local verification on the production NEW splits: QB attn_nn_mae **7.94 → 6.62**, R² −0.074 → +0.239, passing_yards 105 → 67.9 (baseline-level). No new feature column / whitelist / fixture churn; chose train-mean over an `is_depth_chart_missing` flag (8-file churn, constant-in-test for 2025 → no discriminative value).
- **Lesson:** A "cleanup" that improved *semantic* correctness (`-1` represents "missing" better than `3`) regressed the *metric* because the NN consumer was never updated to handle the new sentinel — a deferred follow-up that silently shipped a regression. **Structural rule:** any sentinel value that flows into a `StandardScaler`-fed NN must be in-distribution or imputed before scaling; "-1 = missing" only works if a consumer converts it. **Methodology lesson:** this was an *offline split-build* change (loader.py), so a *runtime* code A/B (baseline vs HEAD pipeline on the same splits) showed **zero** difference — the variable was the data baked into the splits, not the runtime code. Attribute split-refresh regressions by diffing the *splits* column-by-column (row-aligned), not just the code; and don't trust benchmark-history git-blame (the regression's culprit `9409e7e` is the *baseline* commit by benchmark timing, because its 16:14 run predated the 18:50 split rebuild that applied its own loader change). Cross-link: this is the residual layer on top of the `build_features()` restoration below — same "splits refresh broke QB attn" saga, second root cause.
- **Follow-up (2026-05-29 — real root-cause fix, ESPN depth source):** The `-1` impute above was a *consumer-side stopgap* for the underlying gap. nflverse switched the depth-chart source from the NFL Data Exchange to **ESPN** after 2024, so `nfl.import_depth_charts([…2025])` returns the new ESPN schema for 2025 (`dt`/`pos_grp`/`pos_rank` — a daily snapshot series with **no** `season`/`week`), which the legacy `formation=="Offense"` filter silently dropped → zero 2025 coverage. [src/data/loader.py](../../src/data/loader.py) now splits `_fetch_depth` like `_fetch_weekly`: ≤2024 via `nfl.import_depth_charts` (legacy schema, unchanged), ≥2025 read directly from the nflverse `depth_charts` release and normalized back to the legacy 5-column shape by `_normalize_espn_depth` — offense selected via a negative `pos_grp` predicate (`_is_espn_offense`), and the daily snapshots collapsed to per-(player, week) via an **as-of join** on the schedule's `gameday` (latest snapshot ≤ kickoff; leakage-safe since depth charts are pre-game public info). The downstream `min`-rank merge is untouched (the ESPN frame is normalized at the fetch boundary; [src/scripts/audit_features.py](../../src/scripts/audit_features.py)'s 5-column dependency is preserved). 2025 rows now carry **real** ranks, so the `-1` impute degrades to a safety net for genuinely-absent players. Tests: `_is_espn_offense_selects_offense_negatively`, `test_normalize_espn_depth_asof_maps_snapshots_to_weeks`, `test_normalize_espn_depth_empty_when_schedule_incomplete`, `test_load_raw_data_espn_depth_lands_real_rank` in [tests/test_data_loader.py](../../tests/test_data_loader.py). **Unlike the consumer-side fix above, this changes `load_raw_data` output → requires a splits rebuild** for the new ranks to reach training/eval. **Lesson:** a deferred consumer-side stopgap (impute) is not a substitute for fixing the data source; when an upstream provider changes schema, mirror the existing per-source 2025+ fallback (`_fetch_weekly`) rather than papering over the missing column downstream.
