### [FIXED] Analysis prototypes' `_train_attention_holdout` calls broke on the `position` param — the signature guard only spot-checked a kwarg
- **File(s):** [../src/analysis/streams_6pos_prototype.py](../../src/analysis/streams_6pos_prototype.py) (`_build_states`), [../src/analysis/overlap_base_attn_prototype.py](../../src/analysis/overlap_base_attn_prototype.py) (`_run_one`), guards in [../tests/analysis/test_streams_6pos_prototype.py](../../tests/analysis/test_streams_6pos_prototype.py) + [../tests/analysis/test_overlap_prototype.py](../../tests/analysis/test_overlap_prototype.py). PR #1139.
- **What:** `_train_attention_holdout` gained a `position` **first** parameter (trial-data memo keying) after both prototypes were written; their 13-positional calls (+ `opp_source_frames` kwarg) bound shifted and died with `TypeError: missing a required argument: 'feature_cols'`. Both test files carried a `test_depended_pipeline_signatures_unchanged` guard whose stated job was exactly this drift, but it only asserted `"opp_source_frames" in parameters` — so the insertion passed the unit shard and would have surfaced on a GPU benchmark run instead.
- **Fix:** Pass the in-scope position string first in both prototypes (matches the production `run_pipeline`/`run_cv_pipeline` call sites; behavior-neutral otherwise — outside tune workers `cfg.get("trial_data_memo")` is `None`, so the arg is only memo-keying). Tightened both guards to assert the 14-name positional prefix **and** `sig.bind(*range(14), opp_source_frames=None)` — the exact call shape. Positive control: the old shape raises the reported TypeError against the current signature.
- **Lesson:** A signature-drift guard that spot-checks one kwarg doesn't guard — assert the positional prefix the caller relies on and `bind()` the exact call shape (prefix catches insertion/reorder, bind catches arity/new-required-param, and a harmless optional addition still passes). When a private pipeline API grows a param, grep the analysis prototypes too — they call it positionally.
