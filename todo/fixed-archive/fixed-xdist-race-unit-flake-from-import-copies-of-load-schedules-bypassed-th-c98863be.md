### [FIXED] "xdist race" unit flake — from-import copies of `_load_schedules` bypassed the conftest schedules stub; tests also fetched-and-wrote the REAL data/raw cache
- **File(s):** [../src/features/engineer.py](../../src/features/engineer.py) + [../src/shared/team_box_score.py](../../src/shared/team_box_score.py) (late-bind `weather_features._load_schedules` via the module attr), [../src/config.py](../../src/config.py) (`CACHE_DIR` env-overridable via `FF_CACHE_DIR`), [../conftest.py](../../conftest.py) (session redirect of `FF_CACHE_DIR` to a per-session temp dir, symlink-seeded from any real `data/raw`), [../tests/conftest.py](../../tests/conftest.py) (real-`data/raw` write tripwire), regression spy tests in [../tests/test_engineer.py](../../tests/test_engineer.py) + [../tests/shared/test_team_box_score.py](../../tests/shared/test_team_box_score.py).
- **What:** `pytest -m unit` failed sporadically (`FileNotFoundError: data/raw/schedules_2012_2025.parquet` in `build_features` tests; the failing set varied per run, always clustered on one xdist worker; every test passed in isolation) — long misread as an xdist *race*. It is deterministic test pollution: `engineer.py`/`team_box_score.py` held **from-import copies** of `_load_schedules`, so the tests/conftest.py session stub (which monkeypatches the `weather_features` module attr) never reached their call sites — they survived only because the stub also seeds `_schedule_cache`, which the real function returns. `tests/shared/test_weather_features.py`'s autouse fixture then raw-assigned `_schedule_cache = None` with no restore, permanently wiping the seed for the rest of that worker — the next `build_features` consumer on it read the real parquet path. Repro is 100% in ONE process: run that file, then any engineer stint test. Separately, unit tests reached the cache-writing loaders (`load_team_week_stats`, nflcom/sleeper projections) through deep call chains and **fetched real data over the network, writing 0.2–0.7 MB parquets into the real repo `data/raw`** — polluting dev-box caches and racing workers on shared cache builds (the residual #1056/#1057 `ArrowInvalid` family that `atomic_write_parquet` only half-fixed).
- **Fix:** Late-bind the schedules read (`weather_features._load_schedules()`, no from-import copy — patches now actually apply; spy regression tests pin it); migrate the three test patches that targeted the copies. Make `CACHE_DIR` env-overridable (`FF_CACHE_DIR`, the FF_DEVICE shape; production default unchanged) and have the root conftest point it at a per-session temp dir seeded with symlinks to any existing real cache — reads still resolve, writes are isolated (xdist workers inherit the master's env and share the dir; concurrent same-file builds stay read-safe via `atomic_write_parquet`). A tripwire fixture fails any unit test that creates entries in the real `data/raw`.
- **Lesson:** `monkeypatch.setattr(module, name)` never reaches a `from module import name` copy — a comment claiming "the fixture catches this read" is only true if the call site routes through the module attr; spy-test the routing, don't trust the comment. A passing-in-isolation / failing-in-suite test is *ordering pollution* until proven concurrent — bisect by running the suspected polluter file then the victim in one process before reaching for "xdist race". And module-global caches (`_schedule_cache`) reset by raw assignment in an autouse fixture leak across the whole worker session — always reset through `monkeypatch` so teardown restores what the session fixture installed.
