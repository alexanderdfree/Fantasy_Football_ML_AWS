### [FIXED] Upcoming-week builder read an ESPN WAF 403 outage as "offseason" — 20 days of green CI while serving a frozen artifact
- **File(s):** [../src/serving/espn_live.py](../../src/serving/espn_live.py) (`_get_json` UA, `fetch_games(raise_on_error=)`, `next_unplayed_week` + new `EspnUnreachableError`), [../src/serving/upcoming_week.py](../../src/serving/upcoming_week.py) (`main()` strictness, `_publish_artifact` extraction), tests in [../tests/test_espn_live.py](../../tests/test_espn_live.py) / [../tests/test_app_upcoming_week.py](../../tests/test_app_upcoming_week.py), ADR-0018 changelog. PR #1495.
- **What:** Some time after 2026-08-04 14:45 UTC, ESPN's WAF began 403-ing every API request from the `refresh-upcoming-week` CI builder (all 2×18 weekly scoreboard probes, confirmed in run logs through 2026-08-24). The failure chain was silent by construction: `fetch_games` caught the error and returned `[]` (the "never raise into the poller" contract, written for the retired in-serving poller), `next_unplayed_week` read 38 empty probes as `None` = offseason, `refresh_upcoming_week_cache` wrote a local `offseason` artifact and returned **without uploading** (early-return paths skip `upload_artifact_to_s3`), and `main()` discarded the result — exit 0, green check, ~160 consecutive "successful" runs across 20 days. The S3 object (`models/predictions_cache/upcoming_week.json`, LastModified 2026-08-04) never changed, so serving's 10-min download poller faithfully re-served 3-week-old depth charts/injuries/Vegas lines during late preseason. Probing the WAF showed the block keys on User-Agent: the custom `ff-predictor/1.0` and spoofed-browser UAs (`Mozilla/5.0...` from a non-browser TLS client) get 403; honest tool UAs (`Python-urllib/3.x`, `curl/8.5.0`, `python-requests/2.31.0`) pass on all four endpoints used (scoreboard, team rosters, injuries, core depthcharts). The Sleeper fallback (`live_sources.py`, same custom UA) is NOT blocked — left alone.
- **Fix:** (1) `_get_json` sends no custom UA (urllib's honest default), with a don't-"improve"-this-back comment + a test pinning the absence. (2) `next_unplayed_week` distinguishes *verified* offseason (every probe answered, nothing scheduled → `None`) from *unverifiable* (any probe errored and no scheduled week found → raises `EspnUnreachableError`; aborts early after 3 consecutive failures instead of grinding 38 probes × 3 retries against a blocking host). (3) `main()` exits non-zero when the artifact is missing or unavailable for a non-offseason reason (`no_slate`/`no_roster` after a successful detection is inherently anomalous). (4) `_publish_artifact` raises when a **configured** S3 upload fails and only commits `_last_signature` after a successful publish (no-bucket dev/test flows keep best-effort). Verified live: a branch `workflow_dispatch` of the real CI builder on GitHub's runners.
- **Lesson:** For a scheduled builder, "defensive = degrade to empty" inverts into "outage = silence": every network boundary that degrades must have exactly one downstream consumer that can still tell *verified-empty* from *couldn't-verify*, and the job entrypoint must exit non-zero on couldn't-verify — a cron whose failure mode is indistinguishable from success will eventually fail for weeks (here: green CI ≠ fresh artifact, because upload only ran on the happy path). Also: a 403 from an unofficial API is often UA policy, not IP reputation — probe honest tool UAs (`Python-urllib`, `curl`) before reaching for browser spoofing, which modern WAFs *specifically* block when the TLS fingerprint disagrees.
