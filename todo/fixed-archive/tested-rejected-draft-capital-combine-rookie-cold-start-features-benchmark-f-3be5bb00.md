### [TESTED, REJECTED] Draft-capital / combine rookie cold-start features — benchmark-flat; benefit lands only in non-best models
- **File(s):** Fully implemented on a feature branch, then **reverted (never merged)**. Touch points were: [src/data/loader.py](../../src/data/loader.py) (carry `draft_number`/`years_exp` through the roster merge), [src/features/engineer.py](../../src/features/engineer.py) (`_build_draft_features`: `log_pick`/`years_exp`/`is_rookie`/`rookie_log_pick`, baked into the split parquets, + `draft_capital` in `INCLUDE_CATEGORY_ORDER`), and a `draft_capital` INCLUDE category + attention-static entry in each of [src/qb/config.py](../../src/qb/config.py)/[rb](../../src/rb/config.py)/[wr](../../src/wr/config.py)/[te](../../src/te/config.py). Validated via standalone probes + full-pipeline ON/OFF runs (cache-disabled) on regenerated 2012–2025 splits. Full numbers in auto-memory `project_draft_capital_rejected`.
- **What:** Rookies are a cold-start case — every temporal feature (rolling/ewma/prior-season) is 0 in their first NFL weeks and the model has no pedigree signal (can't tell a #2 pick from a UDFA, nor a rookie from a vet). Investigated (1) NFL combine athletic testing and (2) draft capital as a static prior. **Combine: no marginal signal** beyond draft position (partial corr ~0 controlling for pick; combine-only CV R² negative) — rejected outright; would also be a new `import_combine_data` dependency. **Draft capital** has real data-level signal (out-of-time season R²≈0.29–0.35 from `log(pick)`; an *opportunity* prior — corr with volume ≫ efficiency; `draft_number`/`years_exp` already in the roster pull). Encoding: `log(clip(pick,1,300))`, UDFA→258 (best linear transform; `1/pick`/round/raw all worse), gated with `is_rookie×log_pick` since vets carry ~0 marginal signal.
- **Result (real pipeline, ON vs OFF, 2025 test):**
  - **Benchmark (best-model overall MAE) FLAT** at every position: QB +0.006 (best=ridge), RB −0.011 (lgbm), WR +0.010 (attn_nn), TE −0.019 (attn_nn) — all within single-seed/single-season noise.
  - **Rookie-cohort MAE** (the feature's target; rookies are ~14% of rows): benefit is real but concentrated in **LightGBM** (rookies −0.05 to −0.36; first-3-games up to −0.67) plus `years_exp` helping all players. For the *best* model per position it's mixed: RB (lgbm) −0.050 / first-3 −0.204 ✓ and TE (attn_nn) −0.065 ✓, but QB (ridge — already captures the linear signal) +0.008 and WR (attn_nn) +0.077 ✗. Ridge rookies consistently +0.01–0.08; NN/attn rookie deltas are single-seed noise (±0.08).
- **Decision:** Not shipped; reverted to clean. A flat benchmark + an inconsistent rookie effect that only reliably reaches LightGBM (the best model for just RB) doesn't justify the complexity (split-parquet regen, a serving-time `draft_number` data dependency, 16 config entries + fixtures, ongoing maintenance). Clean exception is **RB** (best = LightGBM): if revisited, scope to RB / feed draft capital to LightGBM only, or first add a tracked rookie-subgroup benchmark metric so the win is visible.
- **Lesson:** (1) A quick model proxy can give the **wrong sign** — a reduced-tree, no-early-stopping LightGBM stand-in showed the feature *hurting* rookies (+0.24) while the production 1500-tree/early-stopped LightGBM *helped* (−0.16) on the same rows. Trust `python -m src.{pos}.run_pipeline`, not a stand-in (this is why CLAUDE.md mandates the real pipeline). (2) A feature that improves a *non-best* model doesn't move the benchmark — evaluate the model that's actually selected. (3) A cold-start feature targeting a 14% subgroup is invisible in overall MAE; you need a subgroup metric to judge it, and it must reach the *best* model to matter. Per-row preds for slicing live on `result["test_df"]` (`pred_{model}_total`).
- **Follow-up (2026-05-30):** the "tracked rookie-subgroup metric" precondition now exists — [src/analysis/rookie_cohort_metrics.py](../../src/analysis/rookie_cohort_metrics.py) (read-only diagnostic, no retrain), written up in [src/analysis/rookie_cohort_findings.md](../../src/analysis/rookie_cohort_findings.md). It *reframes* the rejection: rookies are **not** a high-MAE cohort (rookie MAE ≤ veteran MAE at 3/4 skill positions — they score fewer points, so smaller absolute errors), which is *why* an MAE-judged rookie feature reads flat by construction. The real, MAE-invisible defect is **directional bias** — QB/WR/TE over-predict rookies' first ~3 games (QB +3 to +4 FP/g across every model), RB under-predicts throughout (the ascension lag). Judge any future rookie work on `rookie_early` bias + ranking (top-12), not overall MAE.
