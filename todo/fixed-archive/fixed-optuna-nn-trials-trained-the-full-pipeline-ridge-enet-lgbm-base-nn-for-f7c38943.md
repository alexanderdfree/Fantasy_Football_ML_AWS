### [FIXED] Optuna NN trials trained the full pipeline (Ridge / ENet / LGBM / base NN) for an objective that only read attention val loss
- **File(s):** [src/shared/pipeline.py](../../src/shared/pipeline.py) (new `train_ridge` / `train_base_nn` cfg gates with default `True` mirroring the existing `train_elasticnet` / `train_lightgbm` gates; new short-circuit early return after the CPU/GPU branch join when `ridge_test_preds is None or nn_test_preds is None` — skips downstream comparison / prediction attachment / ranking / backtest / save_artifacts / figures, all of which require both prediction dicts), [src/tuning/tune_nn.py](../../src/tuning/tune_nn.py) (`_make_objective` now sets `train_ridge` / `train_elasticnet` / `train_lightgbm` / `train_base_nn = False` per trial; `study.optimize(n_jobs=...)` bumped from 1 to 2 with updated rationale comment), [tests/k/test_attn_pipeline.py](../../tests/k/test_attn_pipeline.py) (new `tuner_shape_pipeline_run` module fixture + `test_tuner_shape_returns_attn_history_and_skips_other_models` asserting the minimal-result shape).
- **What:** [src/tuning/tune_nn.py:235](../../src/tuning/tune_nn.py) calls the position's full `run()` per Optuna trial, which trains Ridge + (optionally) ElasticNet + (optionally) LightGBM + base NN + attention NN. The trial objective at [tune_nn.py:243-251](../../src/tuning/tune_nn.py) only reads `result["attn_history"]["val_loss"]` (per `_make_objective`'s docstring at [tune_nn.py:191-209](../../src/tuning/tune_nn.py): "val-only, no test contamination") — every other model trained inside the trial was wasted compute. Profiling intent (not yet measured on Batch — explicit smoke-trial run withheld per user direction): on g4dn.xlarge `ridge_tune ≈ 6.1 s` (per the 2026-05-21 BLAS-cap entry below) plus base NN training ≈ 10–30 s + LightGBM ≈ 15 s, all gated only by `cfg.get("train_*", default)` with no behavioural dependency from the attention NN side (attention builds its own scaler at [pipeline.py:716](../../src/shared/pipeline.py); no stacking on base NN; explored end-to-end before the change). On top of the wasted compute, [tune_nn.py:573](../../src/tuning/tune_nn.py)'s `n_jobs=1` was forced by the 4-vCPU g4dn.xlarge CPU branch (Ridge tune + LGBM) saturating the box — once skipped, two concurrent attention-NN trials fit comfortably in the T4's 16 GB and the underutilized Tensor Cores.
- **Fix:** Two new `cfg.get("train_*", True)` gates in `_cpu_branch` / `_gpu_branch` (default-True keeps the production training path byte-identical). When both `ridge_test_preds` and `nn_test_preds` come back from the join, the existing downstream block (~155 lines of prediction attachment, weekly backtest, model save, ranking, figure plots — all of which dereference `ridge_test_preds`, `nn_test_preds`, `ridge_model`, `nn_scaler`, `history` unconditionally) runs as before. When *either* is `None`, the new short-circuit returns a minimal result dict (`ridge_metrics`/`nn_metrics` set to None for shape stability, plus `attn_history` / `attn_nn_metrics` / `lgbm_metrics` / `elasticnet_metrics` conditionally if their respective branches ran). Cleaner than guarding every downstream consumer inline — there are too many of them, and they're correlated (skip Ridge ⇒ skip ranking ⇒ skip backtest ⇒ skip figures ⇒ skip save_artifacts). [aggregate_results.py](../../src/tuning/aggregate_results.py) only reads `best_trial` / `best_val_loss` / `best_params` / `n_trials` / `elapsed_seconds` (no Ridge/LGBM/nn_metrics dependency), and no per-position `src/{pos}/run_pipeline.py` overrides the new gates (grep returned empty); the surface area is contained. `n_jobs=2` in `study.optimize` was the second change — viable now that the CPU branch is idle. `epoch_callback` at [tune_nn.py:227](../../src/tuning/tune_nn.py) is thread-safe (`captured` is per-trial-local; `trial.report` / `trial.should_prune` are Optuna-internal). Coverage: the new module-scoped K fixture + test reuses [tests/k/test_attn_pipeline.py](../../tests/k/test_attn_pipeline.py)'s `prepared_splits` / `tiny_kicks` / `outputs_dir` fixtures (so the marginal cost is one extra `run_pipeline` invocation of the K tiny attention path), and asserts: short-circuit fired (`test_df` / `sim_results` / `per_target_preds` absent), skipped models report None, attention NN's `val_loss` trajectory is populated and finite. All 1867 `pytest -m unit` tests + the four K e2e attention tests pass; `ruff check .` + `ruff format --check .` clean.
- **Lesson:** The Optuna objective controls which result fields are *load-bearing*, not which fields the pipeline *produces*. Per-trial pipeline cost defaulted to the wall-clock of every model the pipeline trains, even though the search only optimized one of them — a 1.5–2× compounding waste over the entire tuning sweep (per-trial savings × n_trials × 6 positions). **Structural rule:** when a tuner wraps a pipeline whose objective reads only one sub-component's history, audit `cfg.get("train_*", default)` for every sibling sub-component and disable the ones whose outputs the objective never reads — the audit pays for itself in trial-time savings. The CPU/GPU branch overlap from PR [#267](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/267) (`max(cpu_branch, gpu_branch)` per trial) meant the obvious-looking "GPU is the bottleneck" framing was wrong post-FP16 — the floor was actually the CPU branch's Ridge + LGBM combo, which is what made `n_jobs=2` infeasible. Skipping the CPU branch entirely was the unlock for both wall-clock per trial AND concurrent trials. Companion observation on result-dict design: short-circuit early returns are easier to maintain than per-call-site `None` guards when ~155 lines of downstream code take a hard dependency on a few key dicts. The plan originally called for guarding the `comparison` dict alone; reading [src/shared/pipeline.py:1417-1557](../../src/shared/pipeline.py) revealed the dependency chain extended through ranking / backtest / figures / save_artifacts — too many consumers to guard individually without introducing surface area for partial-state bugs. Cross-link: the per-trial cost estimate in [src/tuning/tune_nn.py:118-124](../../src/tuning/tune_nn.py)'s docstring ("5–10 min locally, 1–2 min on Batch g4dn.xlarge") is now stale on two axes — the 2026-05-21 perf wave (FP16, sync removal, GPU-resident dataset, patience tightening) AND this skip — and the inline comment now points future readers at the remeasurement rather than perpetuating stale numbers.
