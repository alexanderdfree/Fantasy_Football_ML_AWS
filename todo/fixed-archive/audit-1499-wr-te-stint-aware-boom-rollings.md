### [FIXED] WR/TE `opportunity_index_L3` and `redzone_target_share_L3` rolled across team stints
- **File(s):** [src/wr/features.py](../../src/wr/features.py) and [src/te/features.py](../../src/te/features.py) (the boom-tier rolling block), [tests/wr/test_features.py](../../tests/wr/test_features.py), [tests/te/test_features.py](../../tests/te/test_features.py). audit-1499 Tier C-stint PR; issues #1499, #1500.
- **What:** Both team-relative per-game shares (`game_opportunity_index`, `redzone_target_share`) were rolled with `grp = ['player_id', 'season']`, so a mid-season-traded WR/TE's first ≤3 games at the new team averaged in the OLD team's opportunity / red-zone share — the defect class already fixed for `team_wr_target_share_L3` (#674), `team_te_target_share_L3` (#1192) and RB's `opportunity_index_L3` (#1474). Both columns are whitelisted model inputs. Positive control: on the traded fixture the week-7 window {5, 6} read 0.8333 (KC's week-4 0.5 leaking in) instead of 1.0.
- **Fix:** Copy the two per-game columns onto the stint-tagged `df_merged`, roll with `stint_grp`, assign back positionally via `.values` (the RB #1474 pattern); `redzone_targets_L3` stays on the plain grouping because it is the player's raw count, not team-relative. The WR/TE trade tests gained opp-index / redzone-share positive controls and a raw-count negative control. WR + TE Batch benchmark evidence is recorded in the PR.
- **Lesson:** When a stint-aware fix lands for one team-relative rolling, grep every sibling rolling in the same function for `grp` vs `stint_grp` — the boom-tier block was added after the share fix and silently inherited the plain grouping. This is the fourth recurrence of the class (WR → RB → TE → WR/TE), which is the argument for one shared stint-grouping helper (#1383) instead of per-call vigilance.
