### [FIXED] benchmark-batch spliced the unvalidated `image_sha` dispatch input into a `python -c` source string
- **File(s):** [.github/workflows/benchmark-batch.yml](../../.github/workflows/benchmark-batch.yml) (Resolve-image-SHA step, job-definition resolution step, collect step). audit-1499 Tier A PR; issue #1511.
- **What:** The `workflow_dispatch` input `image_sha` flowed through `steps.ctx.outputs.sha` unvalidated into a shell-expanded Python one-liner — `resolve_job_definition('${HEAD_SHA}', boto3.client('batch', region_name='${AWS_REGION}'))` — where a value containing `'` escapes the Python string literal, and was template-spliced (`${{ steps.ctx.outputs.sha }}`) into the collect step's `run:` block. `ab-batch.yml` already rejected non-`^[0-9a-fA-F]{7,40}$` values for the same input; this workflow was the unfiled twin. Dispatch needs write access, so this was defense-in-depth, not an open hole.
- **Fix:** Validate the *resolved* SHA (input or `GITHUB_SHA` fallback) with the same `printf | grep -Eq` regex ab-batch.yml uses, and pass it to the Python one-liner and the collect step through the environment (`os.environ["HEAD_SHA"]` / `--git-hash "$HEAD_SHA"`) instead of string interpolation. A sweep of every `run:` block found no other `${{ }}` splices.
- **Lesson:** When a `workflow_dispatch` input is validated in one workflow, grep the sibling workflows that take the same input name — the security audit's previous filings for this file covered only the `note` input, and the `image_sha` path was invisible to a per-input search. Never interpolate a shell variable into Python source; `python -c` with `os.environ` (or argv) costs nothing and closes the class.
