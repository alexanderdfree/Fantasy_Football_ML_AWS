### [FIXED] PR #280 (tuner-only chore) triggered a full 6-position retrain via `^src/batch/` regex
- **File(s):** [src/scripts/scope_positions.py](../../src/scripts/scope_positions.py) (`_GLOBAL_REGEX` clause `^src/batch/` → `^src/batch/(?!.*(?:tune|ablate))` to exclude tuner/ablation files by name), `src/batch/launch_tune.py` → [src/tuning/launch_tune.py](../../src/tuning/launch_tune.py) (`git mv` so the directory boundary matches the runtime boundary), `tests/batch/test_launch_tune.py` → [tests/tuning/test_launch_tune.py](../../tests/tuning/test_launch_tune.py) (same), [tests/scripts/test_scope_positions.py](../../tests/scripts/test_scope_positions.py) (added `TestSrcBatchTuneAblateExcluded` class with 7 cases pinning the new behavior + a regression case naming PR #280 explicitly), [.github/workflows/retune-nn-batch.yml](../../.github/workflows/retune-nn-batch.yml) (`python -m src.batch.launch_tune` → `python -m src.tuning.launch_tune`), [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md) (D15 References path update), [src/tuning/tune_nn.py](../../src/tuning/tune_nn.py) (docstring reference), [CLAUDE.md](../../CLAUDE.md) (Project shape: warn "tuner code goes in src/tuning/, not src/batch/").
- **What:** Audit of the live AWS Batch queue on 2026-05-21 ~08:00 UTC found 4 GPU jobs (3 RUNNING + 1 RUNNABLE) for image SHA `c2989b06` — PR #280 (`chore(tuning): address second-round review nits`). PR #280's own description: "no behavior change to the tuner or pipeline; mostly comments + one guard + one error handler with test." Only model-relevant file in the diff was `src/batch/launch_tune.py`, the Optuna NN tuner launcher — a separate code path from production training (dispatched via [retune-nn-batch.yml](../../.github/workflows/retune-nn-batch.yml), not [train-batch.yml](../../.github/workflows/train-batch.yml)). The training-detect path uses [src/scripts/scope_positions.py](../../src/scripts/scope_positions.py)::`_GLOBAL_REGEX`, whose `^src/(shared|batch|data|features)/` clause matched `src/batch/launch_tune.py` and fanned out to all 6 positions. Running `git diff --name-only c2989b0^..c2989b0 | python3 -m src.scripts.scope_positions` returned `QB RB WR TE K DST` — false positive of an overly-broad regex.
- **Fix:** Two layers. (1) **Move** `src/batch/launch_tune.py` → `src/tuning/launch_tune.py` (and its test) so the directory matches runtime semantics — all other Optuna/ablation code already lives under `src/tuning/`, which the regex deliberately doesn't include. Updates the workflow caller from `src.batch.launch_tune` → `src.tuning.launch_tune`, the D15 ADR reference, the `tune_nn.py` docstring pointer, and the test imports. (2) **Harden** the regex with a negative lookahead: `^src/batch/(?!.*(?:tune|ablate))`. Files in `src/batch/` whose name contains "tune" or "ablate" are now excluded — belt-and-suspenders against a future tuner/ablation file accidentally placed back under `src/batch/`. Test class `TestSrcBatchTuneAblateExcluded` pins behavior for `launch_tune.py`, `tune_lgbm.py`, `retune_helper.py`, `ablate_thing.py`, nested `src/batch/sub/tune_thing.py`, plus positive controls (`train.py`, `launch.py`, `benchmark.py`, `__init__.py`, `turnaround.py` — confirming "tur..." doesn't false-match "tune"), plus a mixed case (tuning file + training file → still triggers, training wins). Dry-run against the 14 most-recent merge-commits confirmed only `c2989b0`/PR #280 flips verdict (now empty); every other PR keeps its previous behavior. The 4 in-flight Batch jobs were terminated by `aws batch terminate-job` with reason `"PR #280 only touched tuner code (src/batch/launch_tune.py + src/tuning/); no production training change. False positive of overly-broad ^src/batch/ regex."` — DST went straight to FAILED (was RUNNABLE), TE/WR/RB transitioned from RUNNING to FAILED as SIGTERM propagated.
- **Lesson:** A directory-boundary regex (`^src/batch/`) only works if the *directory boundary matches the runtime boundary*. `src/batch/launch_tune.py` shared a directory with `src/batch/train.py` but ran from a different workflow against a different schedule — touching one had no business retraining models trained by the other. Two structural rules to lift from this: (1) when a path-based heuristic gates an expensive action (GPU-hours), every file under that path needs to *deserve* the gate's verdict; if not, move the file or carve out the regex. The negative lookahead `(?!.*(?:tune|ablate))` here is a name-based safety net for the case where someone forgets and places a tuner file in `src/batch/` again — explicit codification of "this naming convention means non-production." (2) When auditing in-flight infra (Batch queue, deploy queue, etc.), distinguish three SHA forms early: the PR branch HEAD (`headRefOid`), the squash-merge commit on main (`gh pr view --json mergeCommit`), and the image tag in container URIs. They're three different hashes, and a 6-char prefix collision between PR #290 (`6618243...`) and PR #292 (`66f984...`) almost misrouted this audit mid-flight. The audit-by-running-the-test rule applies here too: I locally ran `git diff --name-only c2989b0^..c2989b0 | python3 -m src.scripts.scope_positions` and got `QB RB WR TE K DST` — that one command is the verdict, not the audit agent's narrative inference.
