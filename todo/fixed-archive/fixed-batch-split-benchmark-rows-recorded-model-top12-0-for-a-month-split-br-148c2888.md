### [FIXED] Batch-split benchmark rows recorded `{model}_top12 = 0` for a month — split branches never computed `*_ranking`, and the summary defaulted the hole to 0
- **File(s):** [../src/shared/pipeline.py](../../src/shared/pipeline.py) (split/tuning short-circuit), [../src/shared/benchmark_utils.py](../../src/shared/benchmark_utils.py) (`_top12_value`, Top-12 table), [../src/batch/train.py](../../src/batch/train.py) (`_merged_split_metrics` extraction), tests in [../tests/batch/test_train.py](../../tests/batch/test_train.py) / [../tests/shared/test_benchmark_utils.py](../../tests/shared/test_benchmark_utils.py) / [../tests/test_pipeline_e2e.py](../../tests/test_pipeline_e2e.py), PR #1486.
- **What:** Every benchmark_history entry written by the Batch split nn/cpu/merge path since the 2026-06-11 `BATCH_SPLIT_ACTIVE` flip (first zero: `2026-06-11T05-02-55_ed14915.json`) recorded `ridge_top12`/`nn_top12`/`attn_nn_top12`/`lgbm_top12` = 0 for all positions while MAE/R²/RMSE stayed real (true values ≈0.37–0.53). The drop point was the split-branch short-circuit in `run_pipeline`: it returned only `*_metrics` blocks and never called `compute_ranking_metrics`, so branch `benchmark_metrics.json` had no `*_ranking`; the merge job's key-forwarding (`*_metrics`/`*_ranking`) faithfully merged nothing, and `summarize_pipeline_result`'s `result.get("{model}_ranking", {}).get("season_avg_hit_rate", 0)` turned the hole into a plausible-looking 0. ADR-0019's Δ=0.0000 split-vs-monolithic validation compared per-model MAE/R² — not the full summary row — so the missing ranking block sailed through.
- **Fix:** (1) The short-circuit now attaches `{model}_ranking` for every family that trained (same `aggregate_fn` totals + `compute_ranking_metrics` as the full path; guarded on `aggregate_fn` so aggregator-less synthetic configs skip). (2) `summarize_pipeline_result` surfaces a missing ranking as `None` (JSON null) via `_top12_value`, never 0; the Top-12 table renders `—` for None and picks Best over numeric entries only (the serving History tab never consumed top12 — it projects mae/rmse only — and rolling-origin's `_mean_std` already filters None). (3) The merge job's metrics assembly is extracted to pure `_merged_split_metrics` and regression-pinned: branch-metrics-with-rankings → merged → summary asserts all four top12 nonzero; ranking-less branches assert None-not-zero; split-branch e2e pins `ridge_ranking`/`nn_ranking` presence on the real pipeline. Historical zero rows are left as-written (can't be recomputed honestly without retraining those SHAs); the next split run writes real values.
- **Lesson:** A `.get(..., default)` on a *computed* block converts "we never computed this" into a legitimate-looking measurement — default to `None`/absent for anything a consumer might read as a metric, and make parity validations diff the **full summary row**, not just the metric you were changing. Also: when a reduced-mode path (split branch, tuner shape) short-circuits a pipeline, enumerate what the full path attaches afterward and decide field-by-field what the reduced result must still carry — "it returns metrics" hid that rankings, spearman, and the backtest all silently vanished together.
