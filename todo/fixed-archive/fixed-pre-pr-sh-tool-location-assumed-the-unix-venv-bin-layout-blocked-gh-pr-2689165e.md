### [FIXED] `pre-pr.sh` tool-location assumed the Unix `.venv/bin/` layout — blocked `gh pr create` on Windows
- **File(s):** [.claude/hooks/pre-pr.sh](../../.claude/hooks/pre-pr.sh) (the B1 tool-location block).
- **What:** The pre-PR gate located ruff/pytest via `[ -x ".venv/bin/ruff" ]` / `[ -x ".venv/bin/pytest" ]`, falling back to bare `command -v`. On Windows the venv installs to `.venv/Scripts/ruff.exe` / `.venv/Scripts/python.exe` (no `.venv/bin/`), and ruff/pytest are not on the Git Bash PATH (the hook env runs no activated venv), so both resolved to `""` → `fail=1` → "ruff/pytest not found" → exit 2, blocking every `gh pr create` from a Windows + Git Bash box. Worse in the worktree workflow: the hook `cd`s to `$CLAUDE_PROJECT_DIR` (the worktree), but the venv is created once in the **main** worktree, so even a Windows-aware probe of the worktree's `.venv` finds nothing.
- **Fix:** Probe a list of venv roots — `.venv`, then the main worktree's `.venv` resolved from `git worktree list --porcelain`'s first entry — and within each, both layouts: `bin/ruff` → `Scripts/ruff.exe` for ruff; `bin/pytest` → `Scripts/pytest.exe` → `Scripts/python.exe -m pytest` for pytest, before the `command -v` fallback. pytest became a bash **array** (`pytest_cmd=(...)`) because the `python.exe -m pytest` fallback is multiple argv tokens — a scalar `$pytest` would be run as one command name with embedded spaces; it's invoked as `"${pytest_cmd[@]}" -m unit -q` through `run_and_capture`'s `"$@"`. The Unix `.venv/bin/` predicate is byte-identical to the original, so macOS/Linux behavior is unchanged. Verified in Git Bash on Windows against synthetic Unix/Windows/worktree layouts (argv-split, parent-probe, local-wins-over-parent) and against the real parent venv (resolves + runs `ruff 0.15.0` / `pytest 9.0.3`).
- **Lesson:** Cross-platform shell that shells out to venv tools must handle `Scripts/*.exe` vs `bin/*` AND the no-`pytest.exe` → `python -m pytest` multi-token form (→ array, not scalar). In a worktree, the tools may live in the main checkout, not `$CLAUDE_PROJECT_DIR` — resolve the main worktree via `git worktree list` and probe it too. `[ -x ]` is true for `*.exe` in Git Bash (extension heuristic) but false for a touched extensionless file when `core.filemode=false`, so the Unix-layout branch can't be exercised on a stock Windows box — reason about it instead.
