### [FIXED] DST `def_fumble_rec` summed opponent offensive fumbles-lost — undercounted real recoveries ~14% (missed special-teams), a scored 2-pt target head
- **File(s):** [../src/dst/data.py](../../src/dst/data.py) (`build_data` sections 4–5), [../tests/dst/test_data_build.py](../../tests/dst/test_data_build.py) + [../tests/dst/conftest.py](../../tests/dst/conftest.py), audit issue #1427, 2026-07-05 solve-issues tier-C-high PR.
- **What:** `def_fumble_rec` — a scored 2-pt DST target head ([../src/dst/targets.py](../../src/dst/targets.py)) that also seeds `fumble_rec_L3`/`_turnovers` and a per-game attn-history token — was derived by summing the opponent offense's `sack_fumbles_lost + rushing_fumbles_lost + receiving_fumbles_lost` per team-week. That offense-only sum systematically **undercounts** real defensive recoveries: it misses special-teams recoveries (muffed punts, kickoff fumbles) the defense actually recovers, while the authoritative `fumble_recovery_opp` column was already loaded from nflverse `stats_team` in the same function and merged nowhere. Independently reproduced on the real join: 7326 REG team-weeks, 614 mismatches, direct total 4012 vs derived 3436 (~14% low), direct-higher on 585 rows, derived-higher on only 29.
- **Fix:** Source `def_fumble_rec` from `team_stats["fumble_recovery_opp"]` (added to the section-5 `def_team_stats` merge, dropped from the section-4 `def_from_offense` agg); kept `_total_fumbles_lost` (still feeds `team_turnovers`) and the existing 0-fill. Rode along #1393 (drop the dead `opp_scoring`/`opp_fumbles`/`opp_interceptions` per-game compute orphaned when #649 removed their whitelist entries — each was column-identical to `points_allowed`/`def_fumble_rec`/`def_ints` already in the attn sequence). Regression test asserts `def_fumble_rec == fumble_recovery_opp` on a fixture where the offense-only sum is all-zero (the mismatch class). The 29 derived>direct rows are offensive-recovery attribution differences (the offense's own recovery of its fumble is not a defensive takeaway) — `fumble_recovery_opp` is the correct opponent-recovery count. Offline (targets change) → DST retrain; a real benchmark delta is expected on the ~8% of team-weeks whose label moves.
- **Lesson:** When a target-feeding column is *derived* from a component sum, check whether the source already carries the quantity directly — nflverse `stats_team` had the authoritative `fumble_recovery_opp` the whole time, and the component sum silently encoded a different (offense-side) event. A "derived (complete)" docstring comment is not evidence the derivation is *semantically* right; count mismatches against the direct column before trusting either.
