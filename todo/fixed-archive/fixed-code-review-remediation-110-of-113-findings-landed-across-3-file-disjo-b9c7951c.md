- **Lesson:** File-disjointness is a great parallelism primitive for multi-bundle cleanups but does NOT protect against API-signature changes in shared code that downstream consumers in per-position bundles still call. The W.SHARED-A worker dropped the `position` parameter + `val_preds` return from `_train_nn` under L-S10 + L-S11; the W.QB worker (same Tier A PR) independently collapsed `src/qb/diagnose_outliers.py`'s NN loop into a `_train_nn` call under L-QB3 — using the *old* signature it knew about. Cherry-picks landed cleanly because they touched different files; combined `pytest -m unit` passed because no test imports `diagnose_outliers.py` (it's a CLI with `__main__` guard); the broken call site only surfaced at PR-review time when a reviewing agent diffed against the new signature. **Two structural rules to lift:** (1) When a worker bundle touches a shared-code signature, its brief must include "grep for every caller of any function you change" as a discovery step, even if those callers live outside the worker's file-ownership boundary — the worker should *report* the conflict back to the orchestrator rather than silently leaving a broken call site for review to catch. (2) Operator-only CLI scripts (`diagnose_outliers.py`, `analyze_errors.py`, `audit_features.py`, etc.) need *at least* an import-smoke test in their per-position test suite so signature-change drift fails the unit-test shard, not the PR-review pass. Companion process lesson on PR consolidation: a tier-by-risk PR shape (3 file-disjoint PRs, safest → highest-risk training-path) is much easier for the user to review than 12 small PRs but loses the per-bundle CI as a "did this individual change pass tests" signal — to compensate, the orchestrator runs combined pytest+ruff on each tier's staging branch before opening the PR.
