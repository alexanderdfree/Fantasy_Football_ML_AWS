### [FIXED] Season Leaders expert columns deploy rolled back because serving imported analysis-only code
- **File(s):** [../src/serving/core.py](../../src/serving/core.py) (bad import removed), [../src/serving/expert_sources.py](../../src/serving/expert_sources.py) (serving-safe NFL.com scorer + Sleeper/RotoWire loader), [../tests/test_app_expert_predictions.py](../../tests/test_app_expert_predictions.py) (production-import regression guard), [../.dockerignore](../../.dockerignore) (`src/analysis/` exclusion).
- **What:** PR #1090 correctly added NFL.com/RotoWire expert projection columns locally and passed CI, but the ECS deploy rolled back. New task definition `fantasy-predictor:462` used the c458 image and every replacement task exited at import with `ModuleNotFoundError: No module named 'src.analysis'`: `src/serving/core.py` imported `_project_nflcom_to_ppr` and `load_sleeper_with_gsis_id` from `src.analysis`, while the production Docker image deliberately excludes `src/analysis/`. GitHub's deploy workflow returned success because it does not wait for service stability; ECS later marked the task set failed and rolled back to task definition `461`, so the live site kept serving the old Season Leaders UI.
- **Fix:** Move the tiny runtime pieces serving needs into `src/serving/expert_sources.py` and import that from `core.py`; keep the offline analysis package excluded from the serving image. Add a unit guard that parses `src/serving/core.py` imports and fails if serving imports `src.analysis`, plus a direct local import-smoke with `src.analysis` blocked.
- **Lesson:** Production-image boundaries are part of the serving contract. Passing local tests is not enough when the code imports a package excluded by `.dockerignore`; add an import-smoke or static guard for deployment-only exclusions. Also, a deploy workflow with `wait-for-service-stability: false` only proves the ECS update was submitted — verify the ECS task definition/rollout state before saying a user-visible change is live.
