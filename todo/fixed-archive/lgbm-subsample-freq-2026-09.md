### [FIXED] LightGBM row-sampling fractions were inert (`subsample_freq` stayed 0)
- **File(s):** [src/shared/models.py](../../src/shared/models.py) (`LightGBMMultiTarget.__init__`), [src/tuning/tune_lgbm.py](../../src/tuning/tune_lgbm.py) (`_OBJECTIVE_VERSION`), [SETUP.md](../../SETUP.md) (study-name example). Isolated from #1565 (`codex/audit-runtime-correctness` @ `7af61481`, commit `c1df190d`); reproduced against `0f0fec55` in the 2026-09-10 model/data/tuning audit.
- **What:** All six position configurations set `lgbm_subsample` below one (QB 0.867443, RB 0.547198, WR 0.7318847, TE 0.7359385, K 0.8, DST 0.75) and the Optuna tuner sampled the fraction as a search dimension, but `LightGBMMultiTarget` never passed `subsample_freq`, so LightGBM's default bagging frequency of 0 disabled row sampling entirely. The supposedly tuned dimension never affected a fitted tree, and the tuned fractions were selected while inert.
- **Fix:** Pass `subsample_freq=1` whenever the configured `subsample` is below 1.0 (and keep 0 at exactly 1.0, so full-fraction fits stay identical as a positive control). Bump the LightGBM tuning objective namespace to `seedavg_bagging_v2` so corrected trials never mix with studies whose sampled fraction was inactive. `tests/shared/test_lgbm_subsample.py` pins that a partial fraction now matches explicitly enabled bagging and changes predictions, that a fraction of 1.0 preserves legacy predictions, and that `meta.json` and reloads keep the effective frequency. Historical tuned fractions do not establish the corrected recipe's accuracy: the change is metric-bearing for every position's LightGBM model and is held behind the dual-metric + protected-cohort gate (`todo/model-default-repair/README.md`; per-fix isolation arm `fix4` in `todo/audit-model-fix-isolation-2026-09.md`).
- **Lesson:** A hyper-parameter that a library only honors together with a second switch is not configured until the switch is set. Verify that a tuned dimension actually changes the fitted model (a predictions-equal control between the configured setting and the explicitly disabled one) before tuning or reporting it.
