### [FIXED] Architecture tab still described the pre-#870 Huber loss and the retired `val_mae_total` monitor
- **File(s):** [src/serving/frontend/src/views/Architecture.jsx](../../src/serving/frontend/src/views/Architecture.jsx) (Training Loop bullets), [src/serving/routes.py](../../src/serving/routes.py) (`/api/model_architecture` `training_loop.loss`), the rebuilt esbuild bundle [src/serving/static/js/app.js](../../src/serving/static/js/app.js), the regenerated iOS fixture [ios/Tests/Fixtures/client_contract.json](../../ios/Tests/Fixtures/client_contract.json). audit-1499 Tier A PR; issue #1516.
- **What:** The Model Architecture tab told users the loss was "per-target Huber or Poisson NLL" and that early stopping "tracks `val_mae_total`". Since PR #870 every yards head trains on MSE (count heads on Poisson NLL, RB/WR/TE `receptions` on a zero-truncated NegBin hurdle), and the monitor is the loss-weighted validation MAE (`val_mae_weighted` in `src/shared/training.py`; `val_mae_total` no longer exists). The same stale string was served by the backend block and frozen into the generated iOS client-contract fixture. The stale-Huber class had been swept through docs and config comments (#1188/#1391/#1394/#1407/#1417) but never through the serving display surface.
- **Fix:** Corrected both JSX bullets and the routes.py string, rebuilt the committed bundle (`npm run build`), and regenerated `client_contract.json` with `ios/scripts/generate_client_fixtures.py` (hard-gated by `tests/test_client_fixture_generation.py`). Review of the same PR then tightened the per-head wording against every position's `head_losses`: K's four heads are all MSE, DST's common counts (sacks, INTs, fumbles, plus points/yards allowed) are MSE while only its four rare counts are Poisson, the dense `MultiHeadNet` has no `GatedHead` so `src/shared/pipeline.py` downgrades its receptions head from the hurdle to Huber, and the best `state_dict` is restored when the epoch budget runs out as well as on patience (`src/shared/training.py` for/else). Shipped through full CI — rendered response strings are behavioural, so no `[docs-only]` opt-out.
- **Lesson:** A stale-text sweep has three surfaces, not one: source comments/docs, the *rendered* UI copy, and any *generated* fixtures that snapshot the served payload. Grep the frontend sources, the served route strings and `ios/Tests/Fixtures/` together; the committed bundle and the fixture only follow if you rebuild/regenerate. CI reds the PR for only part of that: `frontend-bundle` catches a stale bundle, and `tests/test_client_fixture_generation.py` catches a stale `client_contract.json` — the one fixture `ios/scripts/generate_client_fixtures.py` generates (it now runs in the `serving` shard too, so a serving-only PR can't skip it). `model_architecture.json` is a frozen historical capture kept for decoder backward-compat (`ios/README.md`), so a grep hit for the old copy there is expected, not a miss. The durable fix is to render `data.training_loop` from the API instead of hand-maintaining the same prose in the JSX (follow-up).
