### [FIXED] Upcoming-week inference sliced its frame to one week — every mid-season week served as a Week-1 cold start (+ odds-less slate crash)
- **File(s):** [../src/serving/upcoming_week.py](../../src/serving/upcoming_week.py) (`build_upcoming_week_frame`, `run_upcoming_inference`), [../src/serving/espn_live.py](../../src/serving/espn_live.py) (`fetch_slate`), audit issues #1411/#1400.
- **What:** `build_upcoming_week_frame` featurized the full 2012–now history (scalar rollups correct) but then kept only the upcoming `(season, week)` rows, and `core._apply_position_models` rebuilds every within-season lookback from the frame it receives — `build_game_history_arrays` groups `(player_id, season)` within-frame (one row per group → `pos_in_group == 0` → all-padding history), `add_features_fn` re-derives `shift(1).rolling(3)` L3s (→ NaN → train-mean), QB `season_starts_to_date` cumcounts within-frame (→ 0). Every mid-season week was served with Week-1 cold-start features; the only live validation (2026 W1) was the one week where this is invisible. Separately, `fetch_slate`'s away-side `-g["spread_line"]` had no None guard, so one odds-less game `TypeError`'d the whole 3-hourly refresh and serving silently kept the stale artifact.
- **Fix:** Slice predictions, not inputs: the frame now carries the current season's completed REG weeks + the context-filled synthetic week-W rows (original indices preserved — prediction writes are by index), and `run_upcoming_inference(…, season, week)` filters results to week W after the position loop. No stateful season-to-date artifact — the CI builder rebuilds from raw every 3h; persisting state would add drift/backfill risk for rows that already existed in-frame. The spread negation keeps the parser's deliberate None. Verified by an offline parity check: week-only ≠ weeks-1..W (bug fires), weeks-1..W == full-split predictions exactly on week-W rows (lookbacks are backward-only).
- **Lesson:** A "featurized byte-identically to training" guarantee stops at the columns baked into the frame — anything the downstream path *re-derives from the frame it's handed* (attention history, rollups, cumcounts) needs the same row *context*, not just the same code. And validate lookback features on a mid-season week, never the season opener, where cold-start bugs are structurally invisible.
