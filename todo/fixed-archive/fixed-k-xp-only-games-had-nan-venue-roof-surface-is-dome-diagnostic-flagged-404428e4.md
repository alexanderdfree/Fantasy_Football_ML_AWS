### [FIXED] K XP-only games had NaN venue (roof/surface/is_dome) — diagnostic-flagged segments cleared
- **Files:** `src/k/data.py` (`reconstruct_kicker_weekly_from_pbp` venue backfill from XP plays + `_xp_venue_backfilled` sentinel column, `load_data` schedules-based venue fallback with OAK/SD/STL → LV/LAC/LA remap, `_backfill_2025_pbp_columns` per-game venue lookup with dome wind/temp=0 convention split into a second pass keyed on `(season, week, recent_team)`), `tests/k/test_data_loaders.py` (new `test_reconstruct_weekly_from_pbp_xp_only_game_gets_venue`, `test_reconstruct_weekly_from_pbp_pre_xp_venue_cache_rejected`, `test_load_data_backfills_venue_for_xp_only_games`, `test_load_data_treats_empty_string_surface_as_missing`; updated `_kicker_pbp_cache_row` fixture to include `_xp_venue_backfilled` sentinel and `test_backfill_2025_pbp_columns_updates_in_place` to include `recent_team`). Stale caches need regen on every dev machine + S3 — the sentinel column trips `_cached_pbp_is_current`.
- **What:** The K signal-floor diagnostic (PR #234) flagged two segments on the 2025 test set with anomalously high MAE: `is_dome=NaN` (n=55, MAE 5.259) and `surface=other_or_na` (n=57, MAE 5.119). Both reflected the same root cause — kickers in XP-only games (no FG attempts, n=55) had `roof`/`surface`/`is_dome` as NaN. Three independent sources of the bug: (1) `reconstruct_kicker_weekly_from_pbp` sourced roof/surface from `weekly_fg`'s groupby only, so the outer FG+XP join left XP-only kicker-weeks with NaN venue (affecting 589 rows across 2015-2024 in the cached PBP parquet); (2) `_backfill_2025_pbp_columns` likewise pulled roof/surface from the FG groupby keyed on `kicker_player_id`, missing kickers who only attempted XPs that game; (3) `load_data` had no fallback for either path, so the diagnostic saw 55 NaN rows on test. Two additional surface rows were empty strings (`""`) — PBP occasionally emits these for games nflverse hasn't fully populated (e.g. 2025 KC@LAC week 1). Complementary to the related fix above (`[FIXED] K weather features (game_wind/game_temp) zeroed by catch-all fillna`): that fix made the train-mean-fill take effect for NaN venue rows, this fix eliminates the NaN rows at the source.
- **Fix:** Three layers + cache invalidation. (1) `reconstruct_kicker_weekly_from_pbp` now also extracts `kicker_player_name`/`posteam`/`roof`/`surface` from the XP groupby and fills them as a fallback for the FG-derived columns — XP-only kicker-weeks survive the outer join with venue populated. (2) `_backfill_2025_pbp_columns` builds a second per-game venue lookup from all PBP plays (not just FGs), keyed on `(season, week, posteam)`, and updates k_df in a second pass keyed on `recent_team` — bypasses the FG-attempt requirement entirely; dome wind/temp set to 0.0 to match the historical reconstruction's `.fillna(0)` convention so the model sees consistent train/test distributions. (3) `load_data`'s existing schedule merge was extended to also pull `roof`/`surface` (when present in the schedules parquet) and fill any remaining NaN or `""` values from there; the OAK→LV / SD→LAC / STL→LA team-code remap (cribbed from `src/shared/weather_features.py::_TEAM_CODE_NORMALIZATION`) makes the join hit for pre-2017 rows where schedules carries the historical franchise code. `is_dome` is re-derived from the populated `roof` whenever it was filled. (4) `_xp_venue_backfilled` sentinel column added to `_REQUIRED_PBP_COLUMNS` so stale caches (local + S3) get rejected and regenerated — otherwise train has `is_dome=0` for 589 historical XP-only kicker-weeks while test gets correct labels from the fallback, creating a distribution mismatch. Result on 2025 test: roof NaN 55→0, surface NaN 55→2 (the 2 remaining are unfixable upstream gaps); 589 historical XP-only games regenerated with proper venue (439 outdoor / 150 dome, was 589 outdoor). The K signal-floor diagnostic no longer flags any segments. Total K MAE on test (post both fixes): Ridge 3.992 (was 4.079 baseline), NN 4.025 (was 4.128), Attn 4.075 (was 4.132), LGBM 4.058 (was 4.061). Note: there is a small 0.1 MAE delta vs the `[FIXED] K weather features` standalone state (3.886 Ridge) because correctly-labeled dome games are harder to predict than train-mean-filled ones, but train and test are now in distribution and future feature work isn't built on inconsistent data.
- **Lesson:** When per-play data drives per-game aggregations, anchor on the *game* (`season, week, team`) for game-level attributes like roof/surface/temp/wind, not on the *kicker's attempt* — otherwise any kicker who didn't attempt one of the play types loses those columns to NaN. The bug was hiding behind two layers of "looks right" — the schema check in PR #227 verified columns existed, but didn't catch that 589 of them were NaN; per-target distribution assertions catch zero-collapses but not partial-NaN signals. When a downstream diagnostic flags a segment with a non-trivial n, treat it as a data-quality investigation before dismissing as noise — even a "rejected as not signal-asymmetry" finding can be a real upstream bug. Companion lesson: when a data-prep fix changes the distribution of training data, gate the cache schema on a sentinel column — otherwise the old cache serves the old distribution and only test gets the new fix, creating a silent train/test mismatch that looks like "the new model is worse".
