### [FIXED] tune_nn study namespace keyed on raw FF_CUDA_GRAPH truthiness, not the actual capture decision
- **File(s):** [../src/tuning/tune_nn.py](../../src/tuning/tune_nn.py) (`_resolve_storage_version` + `main()`; `_env_truthy` deleted), docstring contract in [../src/tuning/tune_nn_storage.py](../../src/tuning/tune_nn_storage.py), comment in [../src/tuning/launch_tune.py](../../src/tuning/launch_tune.py); seam tests in [../tests/tuning/test_tune_nn.py](../../tests/tuning/test_tune_nn.py).
- **What:** The residual half of the entry below (#1120, which added the `scheduler_v2_graph` namespace): `main()` resolved the namespace via `_resolve_search_space_version(parallel_backend, cuda_graph=_env_truthy("FF_CUDA_GRAPH"))`. Post-cutover (#889) the env is a force-OFF override, so env-truthiness no longer tracks the trainer: an sm_80+ box (5080, g6/L4, g5/A10G) with the env unset trains GRAPHED but still resolved to the eager `scheduler_v2`/`scheduler_v2_mps` namespaces — so #1120's new namespace was never actually selected on the box it was built for — while a sub-sm_80 box (T4) with `FF_CUDA_GRAPH=1` trains EAGER (the sm gate refuses capture) but resolved to `_mps_graph`. The run-log and results-dict `cuda_graph` provenance told the same lie. The Batch launcher path was unaffected: `launch_tune.py` injects `FF_CUDA_GRAPH` explicitly as the same bool it predicts the namespace with, and the tune CEs (g6/L4, g5/A10G) are all sm_80+.
- **Fix:** `main()` resolves via `_resolve_storage_version(parallel_backend)`, keyed on `cuda_graph_enabled()` — the same autodetect + force-off resolver the trainer consults at capture time — and reuses that bool for the run log and results provenance; `_env_truthy` deleted. No new import cost: `tune_nn` already imports torch at module level via `detect_platform`. MPS workers were already consistent (they receive `storage_version` as an arg and inherit the env, so their capture decision matches the parent's).
- **Lesson:** When a flag's polarity changes from opt-in trigger to force-off override, every consumer that *mirrors* the decision (namespacing, logging, provenance) must switch from reading the env to calling the decision function — at cutover time, grep the env name across the repo, not just the training path.
