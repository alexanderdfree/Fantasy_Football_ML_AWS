### [FIXED] shap>=0.52 (requires-python >=3.12) broke all training/tuning workflows pinned to runner Python 3.11
- **File(s):** [../.github/workflows/train-batch.yml](../../.github/workflows/train-batch.yml), [../.github/workflows/train-ec2.yml](../../.github/workflows/train-ec2.yml), [../.github/workflows/benchmark-batch.yml](../../.github/workflows/benchmark-batch.yml), [../.github/workflows/retune-nn-batch.yml](../../.github/workflows/retune-nn-batch.yml), [../.github/workflows/ablate-scheduler.yml](../../.github/workflows/ablate-scheduler.yml) (runner `python-version` `3.11`→`3.12`, 7 lines).
- **What:** `requirements.txt` pins `shap>=0.52.0,<0.53`, and `shap==0.52.0` declares `requires-python>=3.12`. Five workflows still pinned their GitHub-runner `setup-python` to `3.11`, so their `uv pip install -r requirements-dev.txt` step failed at *resolve* time (`shap==0.52.0 depends on Python>=3.12 … requirements are unsatisfiable`) **before** submitting any Batch job. Net effect: every retrain-triggering merge since ~2026-06-07T10:19 produced **no** training run / no fresh artifacts; the green "train-batch" runs in that window were all docs-only/CI-marker commits whose train job was *skipped* (empty positions). `tests.yml` + `refresh-splits.yml` were already on 3.12, so the test shard stayed green and masked it. Surfaced while verifying PR #989's (cold-start image-slim) post-merge retrain parity — the build succeeded but no benchmark row ever landed.
- **Fix:** Bumped the runner `python-version` to `3.12` in all five lagging workflows, matching `tests.yml`/`refresh-splits.yml` and the project's cp312 standard (numpy/pandas/etc. ship cp312 wheels; the Batch training image itself moved to Ubuntu-24.04/py3.12 in #989). Not a `shap` downgrade — the repo is standardizing on 3.12.
- **Lesson:** A dependency raising its `requires-python` floor breaks **every** workflow still pinned to the old runner Python — but only at the step that *resolves* that dep, and only when that job actually runs, so the docs-only-skip pattern makes it look intermittent (green/red alternating by commit type). Keep `setup-python` in sync across **all** workflows that install the project deps, not just `tests.yml`; `grep python-version: .github/workflows/*` repo-wide when a dep bumps its floor. And confirm "is training actually running?" by a fresh `benchmark_history/` row, not a green train-batch check — a *skipped* train job is also green.
