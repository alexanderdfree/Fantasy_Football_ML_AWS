### [TESTED, REJECTED] vmap stacked seed-ensemble training (Lever C) — same-seed determinism across execution modes is unsatisfiable under fp32+Adam
- **File(s):** [../src/tuning/ab_ensemble_seeds.py](../../src/tuning/ab_ensemble_seeds.py) (shelf prototype, stays merged), dispatch in [../src/tuning/tune_nn.py](../../src/tuning/tune_nn.py) (`FF_TUNE_ENSEMBLE_AB`, inert by default), tests in [../tests/tuning/test_ab_ensemble_seeds.py](../../tests/tuning/test_ab_ensemble_seeds.py). PRs #1138 (harness), #1142 (Adam parity tests + Batch route), #1143 (decision-level gate). Gate reports: `s3://ff-predictor-training/ensemble_ab/RB/report.json`.
- **What:** `torch.func` (`stack_module_state` + `functional_call` + `vmap`) trains N seeds of the attention NN with one host thread — the only true CPU-multiplexing lever for the launch-bound model (homogeneous multi-seed A/Bs). Two L4 Batch gate runs measured **4.4–4.6× speedup** (8 seeds × 30 epochs; stacked ~24 s vs sequential ~108 s) and all machinery proved correct: injected-grad stacked-AdamW parity is **bitwise** (one foreach AdamW over `[N,*]` ≡ N independent AdamWs; stacking is purely layout), post-clip grads match eager at 1e-5, and seed-order swap reproduces identical divergence tables with indices flipped (fork follows the seed, never the slot — no positional bug). But same-seed stacked-vs-eager trajectories FORK: sub-ULP vmapped-batched vs eager kernel rounding hits Adam's sign-like step-1 (`lr·g/(|g|+eps)`, v̂=g²) on near-zero-grad params and amplifies deterministically; on CPU at 3 epochs 2 of 3 seeds fork to ~1e-2 of pred spread (seed 42 stays bit-faithful at ~2e-4), and by 30 GPU epochs **every member** forks (FP fork RMS 0.33–0.77 vs seed-to-seed spread 1.21, worst ratio 0.64 vs the 0.2 gate). Estimated effect on the A/B decision statistic was small (per-member FP-MAE shift ≈ 0.02, common-mode across variants) and a distribution-equivalence gate was designed — **owner rejected the redefinition: the instrument requirement is same-seed determinism, including across concurrent execution modes.** Stacked training structurally cannot provide it.
- **Fix (verdict):** Doctrine stays **1 trial : 1 vCPU** everywhere (tune `--n-jobs auto` → 1:1 on the 4-vCPU Batch shape; multi-seed A/Bs run process-parallel **eager** via ab_harness, which is per-seed deterministic). E2 (`ab_harness --stacked-seeds`) not built. Harness kept as a documented, default-off shelf prototype (TabPFN precedent).
- **Lesson:** Per-seed trajectory bit-parity across kernel implementations is ill-posed under fp32+Adam — vmapped/batched and eager kernels legitimately round differently, and Adam's step-1 `g/√v̂` turns ulp-scale grad noise on near-zero-grad params into full-lr forks that training then amplifies; determinism is achievable only *within* one execution mode (the ADR-0017 graphed-vs-eager framing). Before re-proposing any vectorized multi-model training (vmap ensembles, batched HPO, multi-seed fusing): elicit whether the consumer requires cross-mode same-seed reproducibility FIRST — if yes, the approach is disqualified regardless of speedup, gate design, or correctness proofs. Also: when a validation gate fails on an instrument, the owner's invariant governs over any statistically-motivated gate redefinition — ask before moving the goalposts twice.
- **Update (same day):** the owner REVERSED the rejection for the comparative pipelines after the throughput framing (4.4–4.6×/thread): stacked mode is now an opt-in regime for `ab_harness --stacked-seeds` and tuning (`FF_TUNE_STACKED_SEEDS`), flag-/namespace-separated, with production training unchanged (eager). The determinism finding above still governs the boundary: never compare a stacked arm against an eager arm seed-by-seed. See the levers doc Lever C "REVERSAL" paragraph.
