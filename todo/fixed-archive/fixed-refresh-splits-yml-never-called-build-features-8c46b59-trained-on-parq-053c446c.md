### [FIXED] `refresh-splits.yml` never called `build_features()` — 8c46b59 trained on parquets with 150 engineered cols silently zero-filled
- **File(s):** [.github/workflows/refresh-splits.yml](../../.github/workflows/refresh-splits.yml) (Regenerate step adds `from src.features.engineer import build_features` + `df = build_features(preprocess(load_raw_data()))`; new `Verify engineered columns present` step gates S3 upload by asserting every QB/RB/WR/TE whitelisted feature col (minus runtime-added weather/box-score/specific subsets) is present in `train.parquet`), [src/shared/feature_build.py](../../src/shared/feature_build.py) (`build_position_features` now raises `KeyError` on missing whitelist cols instead of silently `pd.concat`-ing zero-filled columns with a print-statement WARNING), [SETUP.md](../../SETUP.md) (first-time-data-pull snippet matches the workflow), [tests/test_refresh_splits_workflow.py](../../tests/test_refresh_splits_workflow.py) (three new tests: regen step calls `build_features`, verify step gates upload, `build_position_features` raises on missing cols), [tests/test_invariants.py](../../tests/test_invariants.py) (comment update — back-fill path no longer plants zeros), [tests/tuning/test_tune_lgbm.py](../../tests/tuning/test_tune_lgbm.py) (`test_print_best_handles_missing_study` now `monkeypatch.chdir(tmp_path)` so the relative sqlite path doesn't pick up a real tuning study from the project root).
- **What:** PR [#329](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/329) introduced refresh-splits.yml to regenerate `data/splits/*.parquet` in S3 after PR #235 added 5 redzone cols to RB's `attn_history_stats` but the splits parquet was still pinned to the Apr 27 snapshot. PR [#332](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/332) added auto-fire on `src/data/**` / `src/{pos}/config.py` paths; PR [#334](https://github.com/alexanderdfree/Fantasy_Football_ML_AWS/pull/334) dropped the over-strict `verify` gate that had been preventing the workflow from ever shipping (it failed because the position-config union didn't match the parquet schema — a derived-cols problem, not a real schema gap). On 2026-05-21 the workflow finally ran cleanly at 18:48Z. The 8c46b59 Batch benchmark run at 19:08Z consumed those fresh splits. QB ridge MAE dropped from 6.546 → 5.701, LGBM 6.256 → 5.038, but QB attention NN regressed 6.513 → 8.927 with R² going negative (−0.355). Direct diff: old parquet 277 cols / 60 637 rows; new parquet 127 cols / 60 644 rows. The 150-col gap was every engineered feature `build_features()` produces — `rolling_*`, `ewma_*`, `trend_*`, `prior_season_*`, `opp_*`, `is_home`, `days_rest`, `is_returning_from_absence`, `pos_QB/RB/TE/WR` one-hots, etc. Root cause: refresh-splits.yml's Regenerate step ran `preprocess(load_raw_data())` → `temporal_split` with **no** `build_features` step in between. SETUP.md's documented first-time data pull made the same omission. The Apr 27 parquet had `build_features` output baked in (provenance unclear — likely a one-off manual run before SETUP.md was simplified) and had been re-uploaded as-is for weeks. The pipeline's `build_position_features` at `src/shared/feature_build.py:74-89` then silently `pd.concat`'d zero-fill DataFrames for every missing whitelisted col with a single `print(f"WARNING: {len(missing)} feature columns missing, filling with 0")` line that got buried in the Batch CloudWatch logs. Ridge/LGBM improving and attention NN regressing is the expected signature: tree models tolerate redundant features (many of the engineered cols are >0.95 correlated with each other), so removing them under a CV-selected alpha can shift the bias-variance trade favourably on a single test season, while attention NN's static branch genuinely needs those features and degrades clearly. K and DST stayed byte-identical because their data paths (`src/k/data.py`, `src/dst/data.py`) never read `data/splits/`.
- **Fix:** Three layers. **(A) Correctness:** added `build_features` to refresh-splits.yml's Regenerate step (one import, one wrapped call) and mirrored the change in SETUP.md. **(B) Gate:** new `Verify engineered columns present` step runs between Regenerate and `Upload to S3 with force`; reads each skill position's `POSITION_CONFIG.include_features`, subtracts the runtime-added subsets (`WEATHER_FEATURES_ALL` from `merge_schedule_features`, `TEAM_BOX_SCORE_FEATURES + OPP_BOX_SCORE_FEATURES` from `merge_team_box_score_features`, `specific_features` from each position's `add_specific_features`), and raises `SystemExit` if any remaining col is absent from `train.parquet`. **(C) Defense in depth:** `build_position_features` in `src/shared/feature_build.py` now raises `KeyError` on missing whitelist cols, matching the fail-loud contract `build_game_history_arrays` adopted in c06568a. Three new contract tests pin the regen-calls-build_features + verify-step-gates-upload + raise-on-missing-cols invariants. Drive-by: `test_print_best_handles_missing_study` now `monkeypatch.chdir(tmp_path)` so the relative `sqlite:///tune_lgbm_qb.db` storage path doesn't pick up a real tuning study from the project root (surfaced by pre-pr.sh hitting a parent-repo .db left over from an Apr 16 interactive tuning session).
- **Lesson:** Silent zero-backfill of "missing" feature columns produces undetectable model drift. The 8c46b59 swing was caught only because the user looked at the benchmark JSON — the Batch logs had the warning line, but nothing surfaced it. **Structural rule:** when a pipeline encounters missing whitelist columns, the right default is fail-loud (KeyError) — the silent-zero-fill compatibility shim is the kind of "be forgiving on input" pattern that masks regressions and burns days to diagnose. Companion rule on provenance: when SETUP.md and a CI workflow contain near-identical Python snippets that are supposed to produce the same artifact, they ARE the contract — they have to stay in sync, and a change to one without the other is a bug waiting to happen. The Apr 27 parquet's `build_features` output was the contract; the contract was never written down anywhere except in the parquet itself. Cross-link: the failure pattern is the inverse of the H2 archive entry — there, `merge_schedule_features` dropped DST's `spread_line/div_game` and `build_position_features`'s back-fill silently zeroed them; here, `build_features()` never ran and the same back-fill silently zeroed 150 cols. Same back-fill block, two different upstream omissions, both hidden until a metric diff exposed them. Promoting the back-fill to a hard raise closes both classes at once.
