### [FIXED] Batch tune default `--n-jobs auto` died at the ENTRYPOINT — launch_tune's string sentinel vs train.py's `type=int`
- **File(s):** [../src/tuning/launch_tune.py](../../src/tuning/launch_tune.py) (`submit_tune_job` → FF_TUNE_N_JOBS env), [../src/tuning/tune_nn.py](../../src/tuning/tune_nn.py) (`_default_n_jobs_text`), contract tests in [../tests/tuning/test_launch_tune.py](../../tests/tuning/test_launch_tune.py) + [../tests/tuning/test_tune_nn.py](../../tests/tuning/test_tune_nn.py). PR #1153.
- **What:** PR #1119 made launch_tune's `DEFAULT_N_JOBS` the string `"auto"` (resolved in-container by `tune_nn._resolve_n_jobs`) and forwarded it in the containerOverrides command as `--n-jobs auto`. But the container ENTRYPOINT parses argv with `src/batch/train.py`, whose `--n-jobs` is `type=int` — any submission that didn't pass an explicit integer died at argparse with exit 2 (`invalid int value: 'auto'`; Batch job 23b157e3, 2026-06-11). Every earlier Batch tune submission happened to pass explicit numbers (`retune-nn-batch.yml` forwards `--n-jobs $MPS_WORKERS`), so the default path was never exercised until a bare submission hit it.
- **Fix:** `--n-jobs` rides the job environment, never the command: `submit_tune_job` always omits the flag and sets `FF_TUNE_N_JOBS` (the established env-over-argv channel for the fixed ENTRYPOINT — same as FF_TUNE_STACKED_SEEDS / FF_TUNE_AB_SPEC), and `tune_nn`'s `--n-jobs` argparse default reads that env via `_default_n_jobs_text()` (an explicit CLI flag still wins; both paths validate in `_resolve_n_jobs`). `src/batch/train.py` deliberately untouched — editing it fires a 6-position retrain.
- **Lesson:** A launcher *default* that every real caller happens to override is untested contract surface — contract-test the default submission shape (what lands in `containerOverrides`), not just the explicit-flag path. And when a fixed ENTRYPOINT's argv schema can't carry a value (a string sentinel through `type=int`), don't widen the ENTRYPOINT — route it through the env channel that exists for exactly this.
